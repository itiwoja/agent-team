# 勝ち筋の設計要素と提供サービス

公式の加点条件ではない。改善案を考えるときの**設計方針**として使い、要素の個数で加点しない。

## 狙う構造

> **Google Cloud 上のエージェントが、現実・空間・シミュレーションのどれかを観測して、自律的に何かを変え、その結果を再確認するプロダクト**

```
Physical / Spatial / Simulation など LLM 以外の技術
  × Google Cloud AI による Agentic Loop
  × Cloud 上で実際に動くプロダクト
  × Governance / Security / Observability
```

## 設計要素

| 要素 | 意味 |
| --- | --- |
| Physical World | カメラ、センサー、実物、ロボット、IoT |
| Spatial | 2D/3D、AR、GIS、空間認識 |
| Simulation | 物理、群衆、経済、行動、環境などのシミュレーション |
| Generative World | AIが画面ではなく世界・空間・ルールそのものを生成 |
| Closed Loop | 観測 → 判断 → 現実／空間へ作用 → 再観測 |
| Domain Engine | CAD、物理エンジン、ゲームエンジン、GIS、DAW など LLM 以外の強い技術 |
| New Interface | チャット欄ではない操作体験 |
| Agent Governance | 自律性を成立させる制御・検証・証跡（Evidence） |

## 方針

- **LLMを主役にしない。** LLMは判断と計画、検証は専用エンジンや明示ルールに任せる。
- **技術スタックは無理に全部使わない。** その技術がないと製品が成立しない状態の方が強い。
- **Governance は付加機能でなく製品価値に組み込む。** 例：権限外操作をコードで拒否、合否を決定論的に判定、行動をタイムラインで再生。
- **最小デモは1対象・1シナリオに絞る。** 範囲を広げすぎることが最大のリスク。
- **固定ルール・既存手段との比較を用意する。** 「エージェントあり／なし」で同条件の結果を見せる。

## スポンサー提供サービス（利用の有無は審査に影響しない）

| サービス | 提供内容 | 活用の方向 | 留意事項 |
| --- | --- | --- | --- |
| 駅すぱあと API（ヴァル研究所） | 期間中のアクセスキー。電車・バス・飛行機・船の経路検索 | 現実の交通データを観測して判断する Agentic Loop | ダイヤ探索は利用不可 |
| YouCam API（パーフェクト） | 1,000クレジット。画像・動画生成、肌解析、バーチャル試着など50種以上 | 観測結果に応じた生成・解析、New Interface | 機能とクレジット消費は提供仕様に従う |
| GMI Cloud | ミニハッカソン参加者に30ドル分。200以上のAIモデルの推論基盤 | 推論・分析の実行基盤、Observability | 利用条件・期限は提供元の案内を確認 |

サービス呼び出しは単発のデモにせず、観測 → 判断 → 作用 → 再観測の流れに組み込む。
