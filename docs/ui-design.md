# 画面の設計（認知負荷を下げる）

この文書は、`apps/web` の画面を「利用者が覚えること・読むこと・選ぶこと」を最小にする観点で決めた設計です。見た目の決まり（D-100：モノクロ基調・面3段・角丸大）はそのまま使い、情報の置き方と言葉を決めます。

## 3行で

- **1画面1問い**：入口「何を任せる？」、依頼「どうなった？ 私は何をすればいい？」、チェック「私が決めることは？」、担当「誰がいる？」。画面に、その問いに答えないものを置かない。
- **1概念1語**：同じものを2つの言葉で呼ばない（担当／エージェント、チェック／見てほしいもの、任せる／頼む）。
- **いま要るものだけ上に**：「あなたの番 → 結果 → 過程 → 記録」の順。過程と記録は1行にたたみ、動いているときだけ開く。

## 人が判断すべき点

- 「エージェント」を画面から外し「担当」に統一した（アプリ名 AgentTeam と監査ログの語は残す）。製品の説明で「エージェント」を前に出したいなら、入口の1文だけ戻す。

## 原則と根拠

| 原則 | 何をするか | 根拠 |
|---|---|---|
| 認識させる、思い出させない | 戻る先は「ひとつ上」の名前（依頼→依頼、済んだもの→チェック）。画面の名前はメニュー・見出し・タブの題で同じ語 | 再認は再生より速く、誤りも少ない（recognition over recall） |
| 一度に見せる塊を減らす | 依頼のページは3つの塊（あなたの番・回答・担当）。担当はたたむ | 作業記憶に置ける塊は数個。読み飛ばす判断そのものが負荷になる |
| 同じ意味は同じ形 | 行＝1件のカード、丸い札＝状態、○＝見た・送る、琥珀＝あなた待ち、赤＝止まった・失敗だけ、緑＝済み | 形と意味の対応が1対1なら、読む前に分かる |
| 選択肢を増やさない | 同じことをする入口を1つにする（依頼一覧の「新しく頼む」を外し、右下の「＋ 頼む」だけ） | 同じ行き先の入口が2つあると「違いは？」と考えさせる（Hick の法則） |
| 操作はその場に | 送る前の確認の「送らない」「以後も許可」は、行を開かなくても押せる | 主要な判断の選択肢が隠れていると、○ の意味を推測させる |

## 言葉（1概念1語）

| 概念 | 使う語 | 使わない語 |
|---|---|---|
| 依頼から生まれるエージェント | 担当 | エージェント（監査ログの行・アプリ名は例外） |
| `/` の画面 | 入口 | 任せる |
| 頼む操作 | 頼む | 任せる・新しく頼む |
| `/check` の画面 | チェック | 見てほしいもの（画面の中の一覧の見出しにだけ使う） |
| `/asks` の画面 | 依頼 | 依頼の一覧（タブの題だけ） |
| 依頼ごとの集まり | 担当（区画の題） | チーム・編成（文の中では使ってよい） |

## 画面ごとの設計

### 外枠（AppHeader・メニュー）

- ヘッダーは3つだけ：左 ≡、中央「← ひとつ上の名前」、右 チェック（件数）。
- メニューは「入口・依頼・チェック・担当・パック」と最近の依頼。つなぐ（Google カレンダー・GitHub）と費用は「つなぐ・設定」にたたむ。ふだんの行き先5つだけが目に入る。
- 右下の「＋ 頼む」は入口以外の全画面で同じ位置。入口では下の入力欄がその役。

### 入口（`/`）

- 1文・例文3つ・入力欄だけ。変えない。
- 生成中の文は「担当を作っています…」。できた担当は1人ずつ現れ、そのまま依頼のページへ。

### 依頼（`/asks/:id`）

上から、要るものの順に置く。塊は最大3つ。

1. **見出し**：頼んだ文（3行で畳む）。定期なら「毎日7時に動きます · 次は …」の1行。つなぐ案内が要るときだけ1行。
2. **あなたの番**（あるときだけ）：止まった担当の［やり直す］［ここまでで終える］、送る前の確認の行。琥珀の札で「待っているのはあなた」と分かる。
3. **回答**：あなたの文（右の塗り）と担当の報告（左のカード）。前の回答は1行に畳む。止まっているときは「途中で止まっています」の回答カードを出さず、2 のカードに任せる（同じことを2度言わない）。
4. **担当**（1行にたたむ）：「担当 · 2人が同時に作業中 · 顔 顔」。動いている間だけ開き、終わったら閉じる。開くと担当ごとの行（名前・状態・役割・報告）と「受け渡し・実行の詳細」。

幅はほかの画面と同じ 640px。依頼のページだけ 1160px に広がる規則はやめた（画面を移るたびに幅が変わると、視線の起点がずれる）。担当の一覧は3列のグリッドをやめ、1列の行にした。

### チェック（`/check`・ヘッダーのシート）

- 見出しは「見てほしいもの N」。画面の名前は「チェック」で、ヘッダーのボタン・シートの題・メニューも同じ語。
- 行の並びは「送る前の確認 → 質問 → 報告」。種類の札が左上に1つ。
- 送る前の確認は、○（送る）と「送らない」「以後も許可」が開かなくても見える。宛先・中身・ルールは開いたときだけ。
- 済んだものは一覧の末尾の1行から。メニューには置かない（入口を増やさない）。

### 依頼（`/asks`）

- 見出し「依頼 N」、検索、状態の札（すべて・手が要る・動いている・済み・失敗）、日付ごとの行。
- 「新しく頼む」のボタンは置かない（右下の「＋ 頼む」と同じ行き先）。

### 担当（`/agents`）

- 見出し「担当 N」と前置きは1文。行は顔・名前・役割・状態・1行の数字。開くと関わった依頼と仕事。
- スキルの案・外したものがあるときだけ、行の下に1行（「スキルの案が N件 届いています」「使われていないものを N件 外しました」）。開くと「スキル（手順書）」の区画：案（手順はたたむ・○ 使う / × 要らない）→ スキル（育ったスキル・パックのスキルの札）→ 外したもの（戻す）。○ / × / 戻すはオーナーとメンテナーにだけ出す。
- チェックの「育った」の行から `/agents#<担当の id>` で開くと、その担当の行を開いてそこまで動かす。

### パック（`/packs`）

- 前置きは1文（「担当・手順書・スクリプトの詰め合わせです。入れると、そのまま頼めます。」）。

## 色と文字

- 色は意味にだけ使う：琥珀＝あなた待ち・動いている、緑＝済み、赤＝止まった・失敗。装飾の色は使わない。
- 階層は文字の大きさと太さで示す：見出し 22〜24px/700、区画の題 16〜17px/700、本文 16px、補足 13〜14px の `--muted`。線で区切らず、余白（16px）で区切る。
- 押せるものはピル型（`.btn`）か丸（○）。押せないものに影や枠を付けない。

## 変えなかったこと

- ○ で「見た・送る」を表す約束（README の説明と同じ）。
- 届いた知らせのカード（上から降りてきて、その場で見られる）。
- 入口の見た目と、担当が生まれる見せ方。
