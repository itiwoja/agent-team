# 概要

Makase は、依頼文からエージェントのチームを作って仕事を任せるシステムです。エージェントを組む知識（設定・権限・指示文）がなくても、一言頼めば始められます。

## 流れ

1. **頼む**：入口に依頼を書く。
2. **担当が生まれる**：Gemini が依頼文から担当（エージェント）と、その動かし方（並列・まとめ・順番）を決める。案は Kernel の `validateFormation` が検査する。合う担当がすでにいれば新しく作らずに使い回す（[`apps/app/src/asks/planner.ts`](../apps/app/src/asks/planner.ts)）。
3. **動く**：担当が読み取り（Web 検索・ページの取得・カレンダーの空き時間など）をして、結果をまとめる。
4. **確認する**：書き込みの前に、何をするかのカードが届く。○ で実行、× で取りやめ。
5. **記録が残る**：すべての判定と実行は監査ログ（ハッシュチェーン）に残る。

## できること

| 任せ先 | 内容 |
|---|---|
| 調べもの | `web_search`（Gemini の Google 検索 Grounding）・`web_fetch`（許可したドメインの公開ページだけ） |
| Google カレンダー | 空き時間を見て、Makase が作った専用のカレンダーに予定を入れる・消す |
| GitHub | 本人がインストールした GitHub App の範囲でリポジトリを読み、`makase/…` のブランチにコミットして PR を出す |
| 作業場 | 隔離した実行環境（Cloud Run Jobs）でコマンドを動かす |
| 模擬の世界 | 仕入れ係の店舗（受信箱・在庫・発注）。安全チェックと計測に使う |
| パック | よく使う担当の組み合わせをまとめたもの。パックの担当は権限を広げない |

## 使うほど確認が減る

同じ担当を使い回すと、「以後も許可」のルール（1担当に20個まで）や権限を絞った設定が引き継がれ、似た依頼で確認の回数が減ります。モデルの再学習や指示文の自動の書き換えはしていません。権限は、自動では狭くなる方向にしか変わりません。

## 用語

| 用語 | 意味 |
|---|---|
| 担当 | 依頼から生まれるエージェント |
| 書き込み | 外の状態を変える操作（予定の作成・発注・コミットなど）。読み取りと区別して扱う |
| Kernel | 書き込みを「自動・確認・拒否」に判定する決定論のコード（`packages/kernel`） |
| 安全チェック（リハーサル） | 任せる前に悪い日を模擬の世界で走らせる試験（`packages/rehearsal`） |
| 悪い日 | わざと起こす困った状況（F-01 タイムアウト、F-02 仕込まれた指示、F-03 宛先のすり替え など） |
| オラクル | 試験の合否を決める決定論のコード（O-01〜O-08、`packages/oracles`） |
| 締める | 権限を狭くする変更。安全チェックが出す提案はこの方向だけ |
| 合格証 | 安全チェックが全件通った記録。ポリシー・ツール・試験のハッシュとモデル名を含む |
| 汚染 | 外から読んだ内容（Web・メールなど）を信用しない印。汚染のあとの書き込みは Kernel が厳しく判定する |
