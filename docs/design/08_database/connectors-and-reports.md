## TBL-026：workspace_policies（ワークスペースのポリシー）
すべてのエージェントの上限となるポリシー（アプリ内で編集。13 REQ-045・BR-43、[ADR-021](../adr/ADR-021-workspace-policy.md)）。フェーズ0。

| 13・15 に書かれている項目 | 出どころ |
|---|---|
| ワークスペースとの関係：1対1 | 13 §概念モデル |
| 版の履歴を持つ。緩める変更は owner の承認が要る（個人は自分。BR-33） | 13 §概念モデル |
| 内容：`autonomy`（`web_read` / `notify` / `mcp_read` / `mcp_write` / `open_pr`）、`budget`、`web`（`deny_domains`・`max_fetches_per_task`）、`connectors.enabled`、`approvers` | 13 §ワークスペースのポリシー（例） |
| 内容（v0.6）：`rules.enabled`（false なら「以後も許可」を出さず、既存のルールも効かない）、`rules.max_per_agent`（20） | 15 §ワークスペースのポリシー（追加） |
| 1タスクの Intent の上限 `max_intents_per_task`（既定5、Hard Ceiling 20。A-85） | 15 §decide() の拡張 |

- 未設計：カラム・版の持ち方（行を足すか、スナップショットにするか）。Q-65。

## TBL-027：connectors（コネクタ）
登録した MCP サーバー（または組み込みの GitHub）。フェーズ0（URL で登録）、フェーズ1（カタログから OAuth）。

| 13・15 に書かれている項目 | 出どころ |
|---|---|
| ワークスペースが0件以上登録する | 13 §概念モデル |
| 種類：リモートの MCP サーバー（Streamable HTTP）または組み込みの GitHub。ローカルの stdio はフェーズ0のコンテナ内だけ（A-71） | 13 §登録と分類 |
| 登録：URL と認証情報（API キー or OAuth） | 13 §登録と分類 |
| 認証情報は Gateway だけが持ち、暗号化して保存する。サンドボックスと LLM には渡さない | 13 §登録と分類 |
| 無効にできる（無効なら呼び出しは `deny`、`connector_disabled`） | 15 §decide() の拡張 |

- 未設計：カラム・認証情報の暗号化の方式（TBL-013 と同じエンベロープ暗号化かどうか）。Q-65。

## TBL-028：connector_tools（コネクタのツール）
MCP サーバーが公開する各ツールと、その分類・固定のハッシュ。フェーズ0。

| 13・15 に書かれている項目 | 出どころ |
|---|---|
| コネクタに0件以上属する。エージェントとは多対多で、`grant` で使える | 13 §概念モデル |
| `tools/list` で取った ツール名・説明・入力スキーマ・注釈（`readOnlyHint` など） | 13 §登録と分類 |
| 分類：`read` / `write` / `unclassified`（既定。書き込み扱い）。注釈・カタログの推奨は初期値の提案だけ。`read` にできるのは owner だけ（BR-44） | 13 §登録と分類・BR-44 |
| 状態：説明文・入力スキーマが変わったら `needs_review`（確認まで呼び出しは `deny`。BR-42） | 13 §登録と分類 |
| `arg_roles`（jsonb、`{引数名: destination \| content \| option}`）。未確定・新しく増えた引数は `destination`（BR-56） | 15 §データベース |
| `scope`（`self` / NULL）。`destination` がない書き込みツールにルールを付けられるのは `self` を明示したときだけ | 15 §データベース |
| `verify`（`none`（既定）/ `readback`（フェーズ1）） | 15 §データベース |
| `tool_hash`：説明文・入力スキーマ・`arg_roles` から計算する。ルールと Intent はこれに紐づく | 15 §データベース |

- 未設計：カラムの型（`arg_roles` 以外）・キー・ツール名の一意性。Q-65。

## TBL-029：profiles（プロフィール）
自宅・職場・通勤経路・関心のあるテーマなど、ユーザーの個人的な前提（13 REQ-048）。フェーズ0。

| 13・14 に書かれている項目 | 出どころ |
|---|---|
| ワークスペースに0〜1件 | 13 §概念モデル |
| 1ワークスペースにつき50項目、各500文字まで（A-76） | 13 §前提・仮定 |
| 項目ごとに公開先のエージェントを選ぶ。渡すのは定義の `profile` に書いた項目だけ（BR-41） | 13 §概念モデル・BR-41 |
| 質問への答えはプロフィールに保存し、公開範囲はそのエージェントだけにする | 14 §確認する場面を絞る |

- 未設計：カラム・公開範囲の持ち方（項目側に持つか、エージェント定義の `profile` だけで表すか）。Q-65。
