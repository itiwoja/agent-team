# 変更：審査員の入口を「用意した依頼のページ」にする（v0.12 → v0.13、2026-10-02）
> **3行で**：審査員がトークンを入れると、用意しておいた複雑な依頼「仕入れ先のメールを読んで、在庫を見て、必要なら発注して」（受信箱係 → 仕入れ係の順番）のページ SCR-021 に直接入るようにした ／ プロダクトオーナーの要望。開いて10秒で「分けて任せる・統制が効く・リハーサルで裏付ける」が見え、v0.12 で残った Q-109（D-56 と「常に入口」の衝突）も解ける（[D-69〜71](../decisions.md#d-69)） ／ いちばん大きい影響は、1つの依頼の全体を見る画面 SCR-021 が増えたことと、順番の編成の実行がハッカソン版の Must に上がったこと（D-68 を変更）。

## 🧭 判断してほしいこと
- 用意した依頼の送る前の確認（山田珈琲へコーヒー豆 20kg）は、汚染された受け渡しのあとなので BR-70 の「開いた状態」で理由つきで出る想定。ルール・ガードの状態によっては `allow` になって確認が出ないので、デモ用のデータでは「この宛先のルールはまだない」状態で入れる（実装時に E2E で確かめる）。
- 範囲が増えた（順番の生成と実行・SCR-021）。チェックポイント①（10/7）に「受信箱係 → 仕入れ係の一周」を入れた。遅れたときは、入口から頼む依頼だけ「ひとり」に戻し、用意した依頼は残す（切る順番に追加）。
