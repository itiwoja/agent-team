# 2026-10-24 GrokBot の参考資料から取り入れる（v0.6）

- インプット：[参考資料/](../../../参考資料/index.md)（GrokBot のスライド動画のスクリーンショット 14 枚の書き起こし）
- 版数：v0.5 → v0.6

## 3行で
1. 参考資料の 14 枚を今の設計と突き合わせ、合うものを取り入れた（D-191〜D-199）。いちばん効くのは「安い方法から試す」「ページの構造を読む」「スキルの本文は要るときだけ」で、どれもスクショの費用（R-82）を下げる。
2. 「画面の操作は子の文脈で、親には短い報告だけ」は効果が大きいが作りも変わるので、提案（ADR-057、Q-124）にして MS-1 の実測のあとに決める。
3. 「ユーザーごとに残り続ける VM」「ルーチン」「記憶」「声・電話・支払い」は今の方針（タスクごとの使い捨て VM・最初の版を小さく）と合わないので取り入れない。ルーチンと記憶は次の版の候補として 01 §7 に書いた。

## 決めたこと
| ID | 決定 | 決定者 |
|---|---|---|
| D-191 | 道具は安い順に試す：知っていること・手順書 → コネクタ → `web_search`・`web_fetch` → VM のブラウザ → 人に聞く。API が失敗したら Web 検索を飛ばしてブラウザに進んでよい。エージェントの指示の共通部分に書き、Kernel では強制しない | Claude判断 |
| D-192 | スキルは名前と説明（「〜のときに使う」）だけを最初に渡し、本文は道具 `read_skill` で読む。表の形は今の `agent_skills` のまま（`description` を「いつ使うか」に使う） | Claude判断 |
| D-193 | コネクタ（カレンダー・GitHub）の道具は名前だけ先に渡し、使うと決めたときに詳細を読み込む（Claude の tool search）。接続先で使えないときは最初から全部渡す | Claude判断 |
| D-194 | 見るだけの道具 `read_page` を足す。box-agent が CDP のアクセシビリティツリーから、見えているボタン・リンク・入力欄の一覧（役割・名前・中心の座標）を返す。判定しない。秘密の欄の値は返さない | Claude判断 |
| D-195 | 動いているタスクへの持ち主のメッセージは列に並ばず、次の歩みの頭に差し込む（今の `ask_pending_replies` を使う）。LLM の呼び出し中なら中止せず、終わってから入れる。止めたいときは取り消し（API-016）。同じタスクに届いた結果（確認・交代・コマンド）は 1 歩に 1 まとまりで渡す | Claude判断 |
| D-196 | SSE は「合図」にする。事象には通し番号（`workspace_events.id`）・種類・対象の ID だけを載せ、中身は画面が REST で取りに行く。番号が飛んだら・つなぎ直したら、その対象を読み直す。チャットの送信は画面が ID（UUIDv7）を作り、`Idempotency-Key` に入れ、送る前に表示する | Claude判断 |
| D-197 | 知らせは伝える価値があるものだけ。種類は今の 3 つのまま、同じ依頼の同じ種類は 1 つにまとめる（未読の間は件数だけ増やす）。進捗は知らせにせず、依頼のページの表示だけ | Claude判断 |
| D-198 | 確認カードを種類ごとに出し分ける（PR は差分の要約とファイル一覧、カレンダーは予定の中身）。どれも「見せてから ○ か ×」 | Claude判断 |
| D-199 | 失敗したタスクを eval のケースにして、ハーネス（判定・道具の渡し方・指示）を直したら eval で確かめてから出す | Claude判断 |
