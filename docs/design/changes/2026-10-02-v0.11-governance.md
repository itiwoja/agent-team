# 変更：ガバナンスの詰め — ガード・ルールの `option`・汚染の不変条件（v0.10 → v0.11、2026-10-02）
> **3行で**：`decide()` の `approve` の経路を「結果の分からない書き込み → ガード → ルール」の順にした。ルールの `option` は「固定」か「毎回変わってよい」を選べるようにし、変わってよい値はガードで締める。O-03 を BR-39 と両立する形に直した ／ v0.10 で足したガード（BR-61）・オラクル（O-03）・仕入れ係のデモの筋が、Kernel の仕様（FR-004）やルールの形（v0.6）と食い違い、デモの中心の「すり抜け → 締める」が仕様の上で起きなかったため（[D-57〜62](../decisions.md#d-57)） ／ いちばん大きい影響は、[以後も許可] で `option` を「変わってよい」にできるようになったこと（`widen`）。

## 🧭 判断してほしいこと
- [以後も許可] で「変わってよい」にした数値の引数に示す既定の上限（承認した値の2倍）。実機で触って決め直す。
- BR-70 で開いた状態にする「初めての宛先」の範囲（その仕事で初めてか、エージェントで初めてか）。今はその仕事で初めて。
