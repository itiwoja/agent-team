# ADR-040：主役を「任せる体験」に戻し、公開デプロイで本人の Google カレンダーに本当に書き込む
- 状態：承認 ／ 日付：2026-10-09 ／ 決定者：プロダクトオーナー（[D-113](../decisions.md#d-113)）
- 影響する ID：BR-66（部分的に置き換え）, D-41（部分的に覆す）, D-55・D-109（ピッチの主語）, ADR-032, ADR-036, ADR-037

## 状況
ハッカソンのテーマ（使えるエージェント・統制）に合わせてリハーサルを見せ場にした結果、製品の1行目が「任せる前のリハーサル」になった。プロダクトオーナーは、リハーサルを主役にするのは製品の狙いと違うと判断した。作りたいのは、一言頼むとエージェントが生まれて分担し、勝手に片付けて、見てほしいものだけが届く体験。ところが公開デプロイのエージェントが本当に片付けられるのは調べもの（D-111）だけで、書き込み先は模擬の店（sim-world）しかなかった。

## 決定
- 製品の主役を「任せる体験」に戻す。統制・リハーサル・合格証は裏方（任せても大丈夫な理由）として残す。
- 公開デプロイで、**本人が自分でつないだ Google カレンダー**に本当に書き込めるようにする。審査員も自分のアカウントで試せる。
- 守りは [16 §2](../16_google_calendar.md#2-守りd-41br-66-を部分的に覆す理由は-adr-040)：最小の scope（`calendar.app.created`・`calendar.freebusy`）、refresh token は AES-256-GCM（AAD に持ち主）で暗号化し復号は gateway だけ、アダプターは何も持たない、書き込みは全部 ○、通知は送らない、Intent から決まるイベント ID で二重登録を防ぐ、影・リハーサルは本物に出ない。

## 理由
- 任せる体験は、任せた仕事が本人の役に立って初めて気持ちよくなる。模擬の店の発注では審査員にとって自分ごとにならない。
- D-41 が恐れたのは「絞り込み漏れでオーナーの Gmail に届く」こと。オーナーの認証情報を置かず、各自が自分のアカウントを最小の scope でつなぐなら、漏れても届くのは Makase が作った専用のカレンダーの予定と空き・埋まりだけで、既存の予定の中身・メールには届かない。さらに AAD で暗号文を行の持ち主に縛るので、別のワークスペースの行を読んでも開けない。
- カレンダーは「書き込むと本人の画面に結果が出る」ので、○ を押した瞬間の手応えが一番わかりやすい。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 読むだけ（調べもの・まとめ）を広げる | 安全・速い | 「任せた」感覚が弱い | プロダクトオーナーが本物の書き込みを選んだ |
| 下書きまで（送らない） | 統制の見せ場と両立 | 本物の手応えが弱い | 同上 |
| Gmail で送る | ○ との相性が一番よい | 機密性の高い scope で警告画面と審査が要る。他人に届く | 6日で審査は通らない。カレンダーは専用カレンダーに閉じられる |
| Makase が用意した共有のデモ用アカウント | OAuth なしで試せる | 共有アカウントから外へ書ける。濫用の窓口になる | 本人のアカウントのほうが安全で自分ごとになる |

## 影響
- BR-66 は「オーナーの認証情報を置かない。本人がつないだ最小 scope の Google カレンダーだけは例外」に読み替える。15 §公開時のセキュリティ・11 §8 の注記は提出前に直す。
- Cloud Run が4つになる（`gcal` アダプター。sa-gateway だけが呼べる）。
- README・ピッチ・デモの1行目を「任せる」に書き直す（D-55・D-109 のキャッチは裏方の説明へ）。
