# ADR-011：エージェント定義はリポジトリに置き、PR のマージで有効にする
- 状態：**改訂（v0.3）**：GitOps モードとして有効。既定はアプリ内モード（→ [ADR-017](ADR-017-in-app-definition-default.md)） ／ 日付：2026-10-01 ／ 決定者：—（元の記述なし）
- 影響する ID：REQ-021, FR-022, FR-027, US-027, UC-019, NFR-051

## 状況
競合は、エージェントの設定を製品内の画面に持っている。設定画面だけで完結させるほうが簡単である。

## 決定（元の記述・v0.2）
定義の正本はリポジトリ（`.agent/agents/*.yaml`）とし、Web で作った下書きも PR として提出する。有効になるのはデフォルトブランチに取り込まれたときだけ。

## 理由
- 権限の変更がコードレビュー・ブランチ保護・履歴・ロールバックの対象になる。
- 「誰がいつ権限を広げたか」が Git と監査ログの両方に残る。これが競合に対する一番の違いになる。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 製品内の画面に設定を持つ（競合の方式） | 簡単 | 権限の変更がコードレビューの対象にならない | v0.2 時点では差別化を優先（v0.3 で既定として採用 → ADR-017） |

## 影響（元の記述）
- 反映まで PR のマージが必要（試し実行はマージ前にできるので、作る体験は止めない）。
- コードを書かない利用者（P-5）には負担 → フェーズ2のコントロールリポジトリで「PR の自動作成とワンタップのマージ」を検討する、としていた。

## 改訂（v0.3）
- 組織の設定で選べる **GitOps モード** として残す。既定はアプリ内モード（ADR-017）。GitOps モードの組織では、アプリ内の保存は下書きになる（v0.2 の動き）。
- コントロールリポジトリ（REQ-031）は v0.4 でワークスペースのポリシー（REQ-045）に置き換え（[ADR-021](ADR-021-workspace-policy.md)）。
