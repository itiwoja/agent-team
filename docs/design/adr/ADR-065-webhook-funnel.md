# ADR-065：webhook は Tailscale Funnel で受け口だけを公開する（D-128 の例外）
- 状態：承認 ／ 日付：2026-10-24 ／ 決定者：ユーザー（Funnel で受け口だけ）、Claude判断（別の口・署名・上限）
- 影響する ID：REQ-099, FR-096, NFR-064, NFR-085, API-129, TBL-046, R-89

## 状況
きっかけに webhook（GitHub の PR・レビュー・CI の結果など）を入れる。GitHub からの通知はインターネットから届くので、「インターネットに公開しない」（D-128）のままでは受けられない。

## 決定
- 本体は webhook 専用の口（:8081）を別に持ち、そこには `POST /hooks/:hookId` だけを置く。画面と API（:8080）は今までどおり tailnet だけ
- Funnel の公開はポート単位なので、画面と API の 443 番は Funnel にせず（`tailscale serve` だけ）、8443 番だけを Funnel で公開して `/hooks/` を :8081 に流す（v1.1・D-241）。受け口の URL は `https://makase.<tailnet>.ts.net:8443/hooks/<hookId>`。:8081 では Tailscale の身元を見ない（Funnel の通信には付かない）
- 受け口は持ち主が画面で作る（`webhooks`、TBL-046）。`hookId` は推測できない 128 bit の値、署名の秘密は作ったときに 1 度だけ見せる。GitHub は `X-Hub-Signature-256` の HMAC を確かめ、合わなければ 401 で何も残さない
- 本文は 256KB まで。1 分 60 件を超えた分はまとめ、1 時間 600 件で 429。重複は受け口ごとの配達 ID と本文のハッシュで捨てる（v1.1・D-260・D-261）。中身は「信用しない」印つき（汚染）でメインに渡す

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 公開せずに見に行く（GitHub の通知 API を数分おきに読む） | D-128 のまま | 数分遅れる。読みに行く分の費用 | ユーザーが Funnel を選んだ |
| 画面と同じ口で受ける | 口が 1 つ | 公開の口に API が並ぶ | 攻撃面を最小にする |

## 影響
- Funnel を tailnet の設定（ACL の `funnel` の属性）で許す手順を手順書に書く。使わない持ち主は受け口を作らなければ公開されない
- 公開の口への攻撃（R-89）は、署名・上限・別の口で抑える
