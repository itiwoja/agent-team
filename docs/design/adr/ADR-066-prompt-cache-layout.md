# ADR-066：文脈はプロンプトキャッシュの先頭を変えない形に組み、外れはバグとして記録する
- 状態：承認 ／ 日付：2026-10-24 ／ 決定者：Claude判断（参考資料の第 5 章）
- 影響する ID：REQ-105, FR-098, FR-088, NFR-083, TBL-053, `usage_records`, R-93

## 状況
常駐型は同じ会話で長く話すので、1 歩ごとに会話の全部を送り直す費用がかさむ。先頭が前回と同じなら、提供元が計算を使い回せる（プロンプトキャッシュ）。参考資料ではキャッシュに当たらないことをバグと同じに扱い、留守の間に要約する。

## 決定
- 並べる順を固定する：①共通の指示 → ②道具の定義（名前だけのものを含む）→ ③エージェントの指示・スキルの一覧 → ④記憶の写し（プロフィール・ログ 30 件）→ ⑤要約 → ⑥履歴 → ⑦最新。①〜⑥の送った部分は 1 バイトも変えない（追記だけ）。記憶が変わったら、次の `user` メッセージの中に「（本体から：…）」の枠で足す（Messages API の `messages` は `user`・`assistant` だけを受けるので、`role: "system"` のメッセージは使えない。v1.2・D-286）。足した文は歩みの記録に描いた形のまま残し、組み直すときに同じバイトにする（D-277）。古いスクショはサーバー側の context editing で消す
- 道具はターンの途中で足し外ししない。使えないときはエラーを返し、文に次にやることを書く。道具の説明とスキーマは 1 つ 4,000 字まで
- ⑤と⑥の終わりに `cache_control`（1 時間）を付ける
- 呼び出しごとに `cache_read_input_tokens` を記録し、当たるはずの呼び出しで外れたら `cache_miss` として、①〜⑤の部分ごとのハッシュの差を残す（どこが変わったかすぐ分かる）
- メインの会話が 6 万トークンを超え、ターンが終わって 10 分たったら要約する（キャッシュがまだ温かい間）。要約のあとは要約だけを持ち越し、履歴は持ち越さない

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 毎回、最新の記憶を先頭に入れ直す | 記憶がいつも新しい | 記憶が変わるたびにキャッシュが外れる | 費用が膨らむ |
| 要約しない（文脈の上限まで伸ばす） | 細かい情報が落ちない | 遅く高い。上限で止まる | 常駐型で長く話すと持たない |

## 影響
- ホストの状態（SCR-023）に、キャッシュの当たり率と外れの件数を出す
- v1.1：今の Opus 5.5・Sonnet 5.5 は、履歴を書き換えると思考のブロックが無効になる（2026-08-31 以降のアカウントでは 400）ので、追記だけにした（D-256・D-263・D-270）
- v1.2：⑥に足す本体の知らせは `role: "system"` ではなく `user` の中の枠にした（D-286）。要約で汚染の印が消えないよう、先頭にも汚染の印を持たせた（D-278）
