# ADR-042：本体は Node＋SQLite にし、Workflows は歩みの記録に置き換える
- 状態：承認 ／ 日付：2026-10-23 ／ 決定者：ユーザー（歩みの記録の形は Claude判断（提案））
- 影響する ID：FR-084, TBL-038, NFR-071

## 状況
Cloudflare 版は WorkspaceDO の SQLite（同期の repo 関数）と Workflows（やり直し・再開）で動いている。Linux ホストでの土台を決める必要があった。

## 決定
本体は Node 24 の1プロセスと SQLite のファイル1つ（`better-sqlite3`）。repo の同期の関数・kernel・runner・edge はそのまま移す。Workflows の `step.do` は、歩みの記録（`task_steps`）に結果を書いて、再起動のときになぞる形で置き換える。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| workerd を自分で動かす | コードがほぼそのまま | Workflows は自前の運用に対応していない。VM を起こすには別のプロセスが要る | 欠けるところを結局自分で作る |
| 古い Node 版（Postgres）に戻す | 前に動いていた | ラズパイで Postgres が重い。repo を書き直す | 移した成果が無駄になる |

## 影響
- ワークスペースは1つなので、DO の「ワークスペースごと」の区切りはなくなる
- 1つのプロセスなので、書き込みは1本の流れ（`better-sqlite3` は同期）。行のロックは要らないまま
- VM の操作のように繰り返せない歩みは、結果が分からなければ Claude に伝える（FR-084）
