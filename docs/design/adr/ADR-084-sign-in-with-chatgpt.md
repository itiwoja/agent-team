# ADR-084：Sign in with ChatGPT を接続先に足し、キットの初回設定ではこれを先に出す
- 状態：承認（v1.7 への追加） ／ 日付：2026-10-26 ／ 決定者：ユーザー（使う・この形で入れる）・Claude判断（形と安全側の既定）
- 影響する ID：REQ-110・112, US-077・078, UC-066・067, FR-087・107・109・116, NFR-072・094, TBL-059, API-111・152・157, SCR-023・029・033, R-113, D-385〜390。D-384 を更新する

## 状況
非エンジニアにとって一番の壁は API キーを取ることだった（D-384）。OpenAI は 2026-09-29 の DevDay で「Sign in with ChatGPT」を広げ、利用者の ChatGPT アカウントの枠で LLM を呼べるようにした。公式のヘルプセンターには「商用のアプリでプランを使えるのは Go・Plus・Pro。対応しているオープンソースのツールは、すべての ChatGPT の利用者が使える」とある。OSS と手元で動くツールは、秘密の鍵も API キーもなしに自分で登録できる。一方、無料の枠は小さく（Codex の枠を使う）、常駐での使い方・画像・computer use は公式の文書に書かれていない。呼べるのは Responses API だけで、`store: false`・`stream: true` が必須。

## 決定
- 接続先 `openai_chatgpt` を足す。OSS の自分での登録（`dynamic_agent_client`）を使う。使えるモデルはトークンで一覧を取って写す（D-385）
- サインインはデバイスコード（キットが出したコードをスマホで承認）。手元の PC なら `127.0.0.1` の戻りでもよい。トークンは本体に暗号化して置き、VM には置かない（D-386）
- キットの初回設定では「ChatGPT でサインイン」を最初に出す。API キーは別の道として残す。どちらもしなくても家の中のモデルで動く（D-387）
- 403 なら選べない。429 や途中の失敗なら、ほかの支払いに切り替えず止めて知らせる。費用は 0 円、回数とトークンは記録する（D-388）
- 自動のきっかけ（ルーチン・webhook・予約）では既定で使わない（`llm.chatgpt_allow_auto = false`）（D-389）
- 能力は `tools` だけを宣言して始め、画像・computer use は確かめてから足す。ほかのアプリの client を借りる非公式の OAuth は使わない（D-390）

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| API キーだけ（今のまま） | 仕組みが 1 つ | 非エンジニアが最初の一歩で止まる | 壁を取りたい |
| 非公式の OAuth（`openai-oauth` など） | 今すぐ無料でも使える | 公式の登録の道ではなく、利用規約に触れる恐れ | OSS として配る以上、公式の道に限る |
| 自動のきっかけでも ChatGPT の枠を使う | 家の中のモデルが要らない | 無料の枠をすぐ使い切る。常駐での使い方が許されるか分からない | 確かめるまで安全側にする |

## 影響
- 初回設定（FR-109・SCR-033・API-157）にデバイスコードの流れを足す。NFR-094 の 15 分から API キーの段がなくなる
- 確かめること：利用規約（常駐・自動の使い方）、無料の枠の大きさ、画像の入力、computer use の可否（R-113）
