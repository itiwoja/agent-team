# ADR-038：担当どうしは依頼の連絡板で協調し、依頼1件に回答を1つ返す
- 状態：承認 ／ 日付：2026-10-02 ／ 決定者：プロダクトオーナー（[D-72](../decisions.md#d-72)）
- 影響する ID：REQ-066・067（新規）, REQ-064, US-047・048（新規）, US-046, UC-041（新規）, UC-040, FR-063・064（新規）, FR-061・062, BR-73（改訂）, BR-75〜77（新規）, SCR-019・020・021, ADR-036

## 状況
v0.12（ADR-036）で、頼むと編成が生成され、名前の付いた担当が生まれるようになった。ただし担当どうしは、決まった形（まとめ・順番）で結果を一方向に受け渡すだけで、実行中に話せない（BR-73「別の担当を呼べない」）。並列では報告が担当ごとにばらばらに届き、ユーザーから見ると「頼んだことの答え」が1つにならない。プロダクトオーナーは「複数体生成されたら、エージェント同士が協調しながらタスクをこなして、ユーザーに回答してくれる」ことを求めた。1体ならそのままでよい。

## 決定
- 依頼ごとに **連絡板** を作り、同じ依頼の担当だけが `share`（共有）・`question`（質問）・`reply`（返事）・`revise`（作り直しの依頼。まとめ役だけ）を送り合える。連絡は必ず Kernel（`validateTeamMessage()`）を通る。
- 連絡は指示ではなく **データ** として届け、汚染は連絡でも引き継ぐ（BR-75）。連絡で担当・権限・ルール・宛先は増えない（BR-76）。回数・往復・文字数に上限を置く（BR-77）。
- 依頼1件にユーザーへの **回答を1つ** 返す。書くのは編成の **窓口**：ひとりはその担当、まとめはまとめ役、順番は最後の段。並列は LLM を通さず Kernel が担当ごとの報告を並べる。
- ひとりの編成は今までどおり（連絡板を作らず、その担当が答える）。
- 編成は依頼の時点で決めるまま。実行中に担当を足す・依頼の外のエージェントに連絡する・エージェントを作ることはできない（BR-73 を改訂して残す）。

## 理由
- 協調の中身を「話す」に限ると、権限の境界（エージェント）を狭く保ったまま、聞き返し・重複の回避・作り直しができる。書き込みは今までどおり担当ごとの Intent として `decide()` を通るので、連絡で頼まれた送信も統制の外に出ない。
- 汚染を連絡でも引き継げば、「外部のメールを読んだ担当」が別の担当に「発注して」と書いても、受けた担当の送信は汚染されたものとして扱われ、BR-70 で理由つきの確認になる。分けた担当の間で汚染を洗い流す道ができない。
- 回答を1つにすると、ユーザーは担当が何体いても「頼んだ → 答えが来た」だけを見ればよい。SCR-019 の報告の行も依頼1件に1行で済む。
- 並列の回答を Kernel が組み立てると、LLM の呼び出しも、汚染の集まる担当も増えない。
- 窓口を決まった担当にすると（話し合って誰が答えるかを決めさせない）、回答が出ない・二重に出ることが起きない。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 担当どうしが自由に会話する（上限なし・宛先自由） | 柔軟 | 往復が止まらず費用と時間が読めない。依頼の外の担当に広がる | 上限と宛先の検査を Kernel が持つ形にした |
| 担当が別の担当にツールとして仕事を頼む（フェーズ2の委任 REQ-032） | 役割分担がはっきり | 実行中に担当と権限の使い道が増える | ADR-036 と同じ理由でフェーズ2のまま。連絡板は「聞く・伝える」だけ |
| 連絡を共有メモリ（黒板）に書き、全員がいつでも読む | 作りが単純 | 誰が何を読んだか追えず、汚染の引き継ぎを決められない | 宛先と既読を持つメッセージにし、読んだ（差し込まれた）タスクだけを汚染する |
| 並列でも必ずまとめ役を付ける | 回答の文が自然 | LLM の呼び出しが1回増え、汚染が1か所に集まる | 並べるだけで足りる。比べたい依頼は設定プランナーが「まとめ」を選ぶ |
| 回答はエージェントどうしの合議で決める | それらしい | 誰が答えるかが決まらない・二重に答える | 窓口を編成の時点で決める |

## 影響
- BR-73 を「同じ依頼の担当への連絡板での連絡だけはできる」に改訂。BR-75〜77 を追加。
- FR-062 の並列の「結果の受け渡しはしない」に、連絡板の `share`・`question` を追記。US-046 の「報告はそれぞれの行で届く」を「回答1つ」に変更。
- SCR-019 の報告の行は依頼1件に1行。SCR-021 のいちばん上に「回答」、担当の段の間に「やり取り」。
- 新しいテーブル `ask_messages`、`asks.answer_task_id`、`tasks.kind`（`followup` / `revise`）、API-076・077（仮）。08・09 への反映はハッカソンの提出後。
- リハーサル（15）の障害に「汚染された連絡で別の担当に発注させる」を足せる（Should。Q-110）。
