# ADR-060：VM は持ち主に 1 台。残り続け、眠って起きる。画面と Chrome は 1 つで、画面を使う仕事は順番に
- 状態：承認 ／ 日付：2026-10-24 ／ 決定者：ユーザー（1 台・全部共有・画面は順番）、Claude判断（眠り方・数値）
- 影響する ID：REQ-084, REQ-104, FR-074, FR-079, FR-100, NFR-061, NFR-067, TBL-032, TBL-036
- 置き換えるもの：[ADR-048](ADR-048-profile-per-agent.md)（プロフィールはエージェントごと、VM はタスクごと）

## 状況
参考資料のエージェントは、ユーザー 1 人に 1 台の VM を持ち、ファイル・入れたツール・ログインが次に起きたときも残る。v0.6 は VM をタスクごとに使い捨て、プロフィールだけをエージェントごとに残していた。持ち主は「持ち主に 1 台」「画面と Chrome も全部共有・画面は順番」を選んだ。

## 決定
- VM は 1 台（コンテナ `box`）。ホームのボリューム（`makase-vm-home`）にファイル・入れたツール・Chrome のプロフィールを置き、止めても残す。メモリは残さない（Docker のチェックポイントは不安定なため）
- 道具を使うときに起こし、10 分使わなければ止める（眠る）。起きるたびに `boxes` に新しい行（VM の世代）を作る
- 画面と Chrome は 1 つ。画面を使う仕事は「画面の番」（`boxes.screen_task_id`）を 1 つずつ取る。番を待つ仕事は `waiting_screen`。ターミナルは番なしで、別の仕事と同時に動いてよい（2 本まで）
- ログイン状態は全エージェントで共通

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| エージェントごとに残る VM | ログイン・ファイルが混ざらない | ラズパイのメモリが足りない | ユーザーが 1 台を選んだ |
| エージェントごとに画面と Chrome を分ける | 画面の仕事を並べられる | メモリが倍。作りが増える | ユーザーが全部共有を選んだ |
| 今のまま使い捨て | 前の仕事の残りに仕掛けられない | 毎回ツールを入れ直す。ファイルが残らない | 常駐型に合わない |

## 影響
- 前の仕事が残したファイル・Cookie にページの仕掛けが残りうる（R-88）。VM で読んだものは汚染（BR-06）。控えから戻す・作り直す（FR-100）で消せる
- `browser_profiles`（TBL-036）は使わなくなる。ブラウザのデータを消す操作は VM 単位になる
