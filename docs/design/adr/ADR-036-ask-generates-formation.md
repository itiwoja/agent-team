# ADR-036：頼むと編成（エージェント）が生成される。合えば使い回し、必要なら独立した複数のエージェントに分ける
- 状態：承認 ／ 日付：2026-10-02 ／ 決定者：プロダクトオーナー（[D-63〜65・67](../decisions.md#d-63)）
- 影響する ID：REQ-063・064（新規）, REQ-052・058, US-045・046, UC-040, FR-061・062（新規）, FR-034・035・040, BR-71〜74（新規）, SCR-020, ADR-026（作り方を置き換え）, ADR-027, ADR-024

## 状況
v0.5（ADR-026）の作り方は「名前を付ける → 頼む」で、エージェントは1体ずつユーザーが作る。v0.9 で入口を1枚にしたが（ADR-034）、合う担当がいないときは名前を提案して1体作るだけで、1体に向かない依頼（いくつもの調べ物、読んでから送る段取り）も1体で抱える。プロダクトオーナーは「タスクを頼んだら『エージェント生成中…』になり、適したエージェントが生成される。1体より独立した複数が向く場合はそう作る」ことを求めた。

## 決定
- 入口で頼むと、設定プランナーが **編成**（担当と形）を作る。合う担当がいれば使い回し、いなければ名前を付けて新しく作る（D-63）。
- 形は ひとり／並列（それぞれ報告）／まとめ（まとめ役が1つの報告に）／順番（前の結果を次が使う）の4つから、依頼に応じて設定プランナーが選ぶ（D-64）。
- まとめ役は書き込みを持たず、ユーザーへの報告だけをする（D-65、BR-72）。
- 編成の確認は挟まず、すぐ動かす。書き込み・権限が増える所は従来どおり送る前の確認で止まる（D-67）。
- 編成案は Kernel の `validateFormation()` で検査する。LLM の案をそのまま信じない。

## 理由
- 名前を考える・誰に頼むか選ぶ手間がなくなる。「頼むだけ」（ADR-034）を作る側にも広げる。
- 使い回しを優先すると、「以後も許可」のルール・権限を絞った設定・付与が担当に引き継がれ、その依頼で安全チェックを通したあとに承認の回数が減っていく（承認した宛先・安全チェックの結果は仕事ごとで、引き継がれない。D-120）。毎回作ると同じルールをやり直すことになる。
  - D-120 で訂正：引き継がれるのは、定義に入るもの（以後も許可のルール・権限を絞った設定・付与）と担当単位のもの（作業場の控え・スキル）。合格証とリハーサルの結果は仕事ごとで、使い回しても依頼ごとに新しい仕事になるので引き継がれない。
- 分けるのは、権限の境界（エージェント）を狭く保つため。1体に「外部のメールを読む」と「発注する」を両方持たせるより、順番の形で分けたほうが、各担当の付与が少なくなる。汚染は受け渡しで引き継ぐので（BR-71）、分けても防御は弱くならない。
- まとめ役は全員の結果を読むので汚染が集まりやすい。書き込みを持たせなければ、集まっても外へは出ない。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 名前を付けて頼む（v0.5 のまま） | 設計済み | 作る手順が残り、1体に向かない依頼も1体で抱える | 要望に合わない |
| 依頼ごとに毎回新しく作る | 分かりやすい | エージェントが増え続け、承認・ルール・リハーサルが積み上がらない（リハーサルの結果は使い回しでも積み上がらない：D-120 で訂正） | D-63 で不採用 |
| 1体の万能エージェントが内部でサブエージェントを使う | 画面が単純 | 権限の境界が万能エージェント1つになり、付与が最大になる | 境界を狭く保つ方針（ADR-012）に反する |
| 形を並列だけにする | 作るものが少ない | 「調べて比べる」「読んでから送る」が表せない | D-64 で3つを使い分けると決めた |
| エージェントが自分で別の担当を呼ぶ（フェーズ2の委任 REQ-032） | 柔軟 | 実行中の LLM の判断で担当と権限が増える | 編成は依頼の時点で決め、実行中は増やさない（BR-73）。委任はフェーズ2のまま |

## 影響
- FR-034（名前を付けて作る）はメニューの奥のエージェント一覧に残す。日常の作り方は FR-061。
- FR-040 の「新しいエージェントを勝手に作らない」は、エージェントのチャットで頼んだ場合に限る。01 の Won't を書き換えた。
- 新しいテーブル（`asks`・`ask_members`）と API（API-072〜074）、`tasks.ask_id`・`input_task_ids` が要る。08・09 への反映はハッカソンの提出後。
- テンプレートにまとめ役（読むだけ・報告だけ）を足す必要がある。ADR-013（テンプレートは固定）の範囲で、`briefer` を書き込みなしで使うか新しく足すかは実装時に決める（A-101）。
- リハーサル（15）は、順番の編成は編成全体で1回、並列・まとめは担当ごとに行う（v0.13）。
- 1つの依頼の全体を見る画面 SCR-021 を足した（v0.13、D-69）。
- v0.14（[ADR-038](ADR-038-team-board-and-one-answer.md)）：担当どうしが同じ依頼の連絡板で協調できるようにし、依頼1件に回答を1つ返すようにした。BR-73 は「依頼の外の担当を呼べない」に改訂して残す。
