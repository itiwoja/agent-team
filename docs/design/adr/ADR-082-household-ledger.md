# ADR-082：レシートの写真から家の中だけの家計簿を作る
- 状態：承認（v1.7） ／ 日付：2026-10-26 ／ 決定者：ユーザー（家計簿）・Claude判断（形）
- 影響する ID：REQ-114, US-080, UC-069, FR-112, NFR-097, TBL-061, API-154, SCR-031, R-108, D-375

## 状況
ユーザーの例：「レシートの写真を送ると、カレンダーとレシートの情報で、家の中で家計簿ができる」。家計簿は家の外に置きたくない情報で、家に置く常駐エージェントの分かりやすい使い道になる。

## 決定
- チャットでレシートの写真を送る → 画像を読める役割が店・日付・品目・金額・支払い方法を読む → 費目は仕分けの役割 `classify`（自信が低ければ LLM。ADR-083）→ `ledger_entries` に入れる（D-375）
- カレンダーの同じ日の予定と照らし、メモに付ける（例：「家族で外食」）
- 金額・日付の読み取りの自信が低いときは、確認のカードで持ち主に直してもらう
- レシートの画像は保管庫の `レシート` に、家計簿は家の中の SQLite にだけ置く。月ごとの画面と CSV の書き出し
- 目標：試しのレシート 50 枚で、金額・日付 95% 以上、費目 90% 以上（NFR-097）

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 家計簿のアプリ（クラウド）につなぐ | 機能が多い | 家の外に置く。アプリごとに API が違う | 家の中に置くのが売り |
| 文字の読み取り（OCR）だけで作る | 0 円・家の外に出ない | レシートの形がばらばらで、品目と金額の対応を読み違える | 既定はクラウドの画像を読める役割（ユーザー） |

## 影響
- 写真は台帳に残る（R-108）。家に GPU の PC があれば、画像を読む役割をローカルに切り替えられる（ADR-078）
