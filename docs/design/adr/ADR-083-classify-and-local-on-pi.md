# ADR-083：仕分けは判断モデルで家の中で行い、ラズパイでは 4B 級までの生成モデルを軽い役割に使う
- 状態：承認（v1.7） ／ 日付：2026-10-26 ／ 決定者：ユーザー（判断モデルを使う・4B を売りに）・Claude判断（使う場面の線引き）
- 影響する ID：REQ-117, US-083, UC-072, FR-107・115, NFR-092・096, TBL-059, BR-16, R-109・112, D-379・380。D-357 を置き換える

## 状況
Jev（TypeSafe AI）型の判断モデルは、文章を生成せず、選択・点数・はい/いいえを型つきで返す。OSS の似たもの（Von 約 4 億、Laya 3〜4 億・多言語、Rizzo Flow 17〜40 億・llama.cpp）が出ていて、小さいものは CPU で動く。ユーザーの友人によると、ラズパイ 5（8GB）で 4B のモデルが動いた。v1.6 の D-357 は「ローカル LLM の推論サーバーはラズパイに置かない」だった。

## 決定
- 役割に `classify`（仕分け）を足す。接続先 `decision`（Kev の `/v1/systemone` 互換、または OpenAI 互換で選択肢の確率を返すもの）で判断モデルを呼ぶ（D-379）
- 使う場面は、間違えても困らない仕分けだけ：レシートの費目、知らせる価値があるか、振り分けの下ごしらえ、家電への短い指示で機器と操作を選ぶ（選んだあとの判定は Kernel）
- Kernel の判定・こわい操作・機器の区分には使わない（BR-16）。自信が下限（既定 0.8）より低ければ LLM に回す
- ラズパイ 5 では 4B 級（量子化）までの生成モデルを、`summary` と短い文章の役割に限って選べる。`main`・`worker`・`computer` には使わない。8GB では VM を起こしている間は止める（D-380）
- どちらも、日本語の精度・速さ・メモリ・ライセンスを実機で確かめてから既定にする（R-109・R-112）

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 仕分けもクラウドの LLM | 精度が高い | 1 件ごとに費用と待ちがかかる。家の外に出る | 家の中で 0 円・一瞬が売りになる |
| 判断モデルを Kernel の判定にも使う | 柔らかく判定できる | 間違える。判定を再実行で確かめられなくなる（ADR-076） | B を崩す |
| ラズパイにはローカルのモデルを置かない（D-357 のまま） | メモリに余裕 | 「ネットが切れても家の中で片付く」が言えない | 4B が動くという報告がある |

## 影響
- `llm_models` に接続先と能力 `decision` を足す
- キットの推奨を 16GB にする（NFR-092）
- 試験に、ラズパイでの判断モデルと 4B の実測を足す（11）
