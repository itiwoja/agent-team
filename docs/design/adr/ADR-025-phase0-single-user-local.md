# ADR-025：最初の到達点を、単一ユーザー・ローカルで動くフェーズ0にする
- 状態：承認 ／ 日付：2026-10-01 ／ 決定者：ユーザー（13 の決定事項）
- 影響する ID：REQ-051, A-01, NFR（フェーズの列。[05](../05_non_functional.md)）

## 状況
課金や SaaS の運用は当面不要で、まず自分で毎日使える状態にしたい（2026-10-01 決定）。

## 決定
docker compose で動く単一ユーザー構成をフェーズ0とする。Kernel・監査ログ・Intent はフェーズ1と同じものを使う。マルチテナント・クラウドの構成はフェーズ1以降に実装する（設計は残す）。

## 理由
プロダクトオーナーの開発環境で動けば十分で、SaaS 化はその後でよい。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| ベータで500ユーザーの SaaS を最初の到達点にする（これまで） | — | 課金・SaaS の運用が先に要る | 上記の状況 |

## 影響
- 「セルフホスト版は作らない」（01 の制約）を、**フェーズ0の開発・自己利用に限って** 緩める。公開するセルフホスト版は引き続き作らない。
- フェーズ0ではサインイン・マルチテナント・RLS・Cloud Run・KMS によるチェックポイントの署名・SLA を省略する。構成の違いは [07 §フェーズ0とフェーズ1以降の違い](../07_architecture.md#フェーズ0とフェーズ1以降の違い)。
