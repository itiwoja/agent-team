# ADR-037：入口を「仕事はエージェントに任せて」と入力欄だけにし、チェックを別の画面に分ける
- 状態：承認 ／ 日付：2026-10-02 ／ 決定者：プロダクトオーナー（[D-66](../decisions.md#d-66)）
- 影響する ID：REQ-065（新規）, SCR-020（新規）, SCR-019（`/` → `/check`、頼む欄を廃止）, ADR-034（一部を置き換え）, D-56

## 状況
v0.9（ADR-034）は「頼む・チェック」を1枚にし、頼む欄を画面の下に置いた。プロダクトオーナーは、最初の画面を真ん中に「仕事はエージェントに任せて」とだけ出し、その下に入力欄を置く形にしたいと考えた。いつ出すかは「見るものがないときだけ」「初回だけ」「常に入口」の3案から、常に入口を選んだ。

## 決定
- `/` は SCR-020「任せる」：中央に1文、その下に入力欄、さらに下に「見てほしいもの N ・ 動いている N」の小さな件数だけ。
- SCR-019 は「チェック」として `/check` に移し、頼む欄をなくす。入口の件数・通知・「← 任せる」で行き来する。
- 頼むと SCR-020 の1文の位置が「エージェント生成中…」になり、編成を見せてから入口に戻る（ADR-036）。

## 理由
- 開いた瞬間にすることが「頼む」1つだと分かる。行が並んだ画面では、頼むより先に読むことが始まる。
- 頼む所とチェックする所を1つずつにすると、どちらの画面でも操作が1種類になる。
- 止まっている仕事（送る前の確認）は、件数の色で入口からも気づける。通知は SCR-019 の該当の行に直接入るので、承認までのタップ数（NFR-041）は変わらない。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 見るものがないときだけこの形（SCR-019 の空の状態） | 画面が1枚のまま | 行があるときは入口の印象が変わる | プロダクトオーナーが「常に入口」を選んだ |
| 初回だけ | 最初の印象を作れる | 2回目からは v0.9 と同じ | 同上 |
| 頼む欄を SCR-019 にも残す | チェックの途中でも頼める | 頼む所が2つになり、生成中の見せ方も2通り要る | 操作を1つずつにする方針に反する |

## 影響
- ハッカソン版の D-56（入口の直後にリハーサルの結果を開く）とぶつかる → D-69 で、審査員はトークンを入れた直後だけ、用意した依頼のページ（SCR-021）に入ることにした。Cookie で戻ったときは SCR-020。
- 通知・`?item=` の URL を `/check?item=` に変える。
- ADR-034 の承認の操作（○ と5秒の取り消し）・行の種類・メニューは変えない。
