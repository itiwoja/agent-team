# ADR-026：エージェントの作り方を「名前を付けて頼む」にし、設定はエージェント自身が行う
- 状態：承認 ／ 日付：2026-10-01 ／ 決定者：ユーザー（14 の決定事項）
- 影響する ID：REQ-052〜058, REQ-020（置き換え）, FR-024（置き換え）, SCR-015（廃止）, SCR-018

## 状況
v0.3 までの作り方（会話で下書き → Canvas → 試し実行 → 公開）は、開発者には安心だが、一般の個人ユーザーには手順が多い。プロダクトオーナーは「やりたいことを伝えるだけで、最適化されたエージェントが動き、続ける」体験を求めている。

## 決定
②を採る。エージェントは名前のある担当者として見せ、設定（テンプレート・ツール・コネクタ・トリガー・届け先）はエージェント（設定プランナー）が会話から決める。Canvas と YAML は詳細設定に残す。

## 理由
作成の手順が「名前を入れる → お願いする」の2つになる。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| ① エージェントを隠し「お願い（ゴール）」だけを見せる | — | — | ②を採用（担当者として見せる） |
| 会話で下書き → Canvas → 試し実行 → 公開（v0.3 まで） | 開発者には安心 | 一般の個人ユーザーには手順が多い | 上記の状況 |

## 影響
- 設定の正しさを人が事前に確かめる機会が減るため、`classify()`（[ADR-027](ADR-027-classify-widening-changes.md)）と変更の記録・元に戻す操作で補う。
- 設定プランナーは `api` の中で動き、LLM Proxy を通す（[07 §設定プランナーの位置](../07_architecture.md#設定プランナーの位置)）。
