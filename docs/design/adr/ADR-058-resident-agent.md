# ADR-058：常駐型にする（ループと状態は本体に置き、きっかけで起き、用がなければ眠る）
- 状態：承認 ／ 日付：2026-10-24 ／ 決定者：ユーザー（常駐型として作り直す）、Claude判断（眠り方・数値）
- 影響する ID：REQ-096〜100, FR-090, FR-091, FR-094〜096, TBL-041, TBL-042, NFR-082

## 状況
v0.6 までは、持ち主がチャットで頼んだときだけ動く。参考資料（GrokBot の講義の解説動画）の「常駐型」は、ループと状態をサーバーに置き、持ち主の入力以外（時刻・外の出来事・裏の作業の完了）でも起き、用がなければ処理もコンピュータも眠る。持ち主はこの形で作り直すことを選んだ。

## 決定
- エージェントのループと状態（会話・記憶・ルーチン・スキル・歩みの記録）はすべて本体の SQLite に置く。VM には状態を置かない（VM を作り直しても会話は消えない）
- 起こすきっかけは 5 つ：持ち主のチャット・ルーチン・予約した確認・webhook・裏の作業の完了。受付がきっかけを `wakes` に入れ、ルーターが重複を捨ててキューに並べる（FR-090）
- メインのターンは「起きる → 歩む → 眠る」。歩みは今の歩みの記録（TBL-038）で耐久性を持たせ、落ちても止まった歩みから続ける。何もないときは LLM を呼ばず、VM は 10 分で止める
- 作業の後、伝える価値がなければ何も送らない（ADR-062）

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 今のまま（頼んだときだけ動く） | 作る量が少ない | 留守の間に進まない。外の出来事で動けない | ユーザーが常駐型を選んだ |
| Temporal などのワークフローエンジンを入れる | 耐久性が強い | ラズパイに重い。コンテナが増える | 歩みの記録（ADR-042）で足りる |
| ずっと LLM を回し続ける（見張り役） | 反応が速い | 待機中も費用がかかる | 待機中はほぼ無料にする（NFR-082） |

## 影響
- 「依頼（ask）」を中心にした作りは、1 本のチャット（`chat_messages`）・メインのターン（`turns`）・仕事（`tasks`）に置き換わる（ADR-059）
- タイマー（毎分）がルーチンと予約した確認の時刻を見て、きっかけを作る
