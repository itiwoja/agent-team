# ADR-067：Web Push の通知を最初の版に入れる
- 状態：承認 ／ 日付：2026-10-24 ／ 決定者：ユーザー
- 影響する ID：REQ-091, FR-017, FR-093, API-031, API-032, TBL-037, NFR-086
- 覆すもの：D-179（Web Push は次の版）

## 状況
v0.6 では、知らせは PWA を開いているときの SSE だけだった（D-179）。常駐型では、留守の間に終わった仕事・確認・交代の頼みを持ち主に届けることが要になる。

## 決定
- PWA の Web Push（VAPID）を入れる。鍵は `.env` の `VAPID_PUBLIC_KEY`・`VAPID_PRIVATE_KEY`
- 送るのは、`send_to_owner` の `notify = true`・人の確認・交代の頼みの 3 つだけ。オートレビューで通った操作・進捗は送らない（D-197）
- 同じ仕事の同じ種類は 1 つにまとめる（`tag` を同じにして置き換える）。PWA が前に出ているときは送らず、SSE だけ
- 購読は端末ごと（`push_subscriptions`）。送れなかった購読（404・410）は消す

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 今のまま SSE だけ | 作りが単純 | 開くまで気づかない | ユーザーが入れることを選んだ |
| メール・Slack で知らせる | 確実に届く | 窓口が増える | 窓口は PWA だけ（01 §7） |

## 影響
- iOS は「ホーム画面に追加」した PWA でだけ届く。手順書に書く
- Push のサービス（Apple・Google・Mozilla）を通るので、通知の文には中身の要約だけを入れ、秘密は入れない
