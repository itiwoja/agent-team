# ADR-044：VM を起こせるのは box-manager だけにする
- 状態：承認（2026-10-24 にユーザーが承認：D-172） ／ 日付：2026-10-24（v0.2 で中継の役割を直した） ／ 決定者：Claude判断（提案）→ ユーザー
- 影響する ID：FR-074, FR-100, API-101〜109・113・143・146, NFR-066, R-79

## 状況
VM を起こすには Docker を操作する権限が要る。Docker のソケットを持つものはホストを握れる。本体は外のページの内容と LLM を扱うので、乗っ取られる面が広い。

## 決定
Docker の権限は、別のコンテナの box-manager だけに持たせる。box-manager は「決まったイメージを決まった上限で起こす・止める・VM ごとのネットワークを作る・一覧・中継・プロフィールを消す」しか受けず、作るコンテナの中身（イメージ・マウント・権限・ネットワーク）はコードで固定する。ソケットは docker-socket-proxy を通し、使う API の種類（コンテナ・ネットワーク・ボリュームの作成と削除、イメージの読み取り）に絞る。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 本体にソケットを渡す | 部品が1つ減る | 本体が乗っ取られるとホストを握られる | 守りが薄い |
| rootless の Podman | ソケットの危うさが小さい | ラズパイ・WSL での手順が増える | 手順を1つにしたい（ADR-049） |

## 影響
- docker-socket-proxy は API の種類を絞るだけで、作成の中身までは絞れない。box-manager が乗っ取られれば、権限つきのコンテナを作られてホストを握られる（R-79 は残る）。box-manager を小さく保ち、外から届く口を ctl だけにする
- 本体と box-manager の間は共有トークンで確かめる
- v1.0 から VM は 1 台・box ネットワークは 1 本（ADR-060）なので、決定の「VM ごとのネットワークを作る」は「決まった box ネットワークにつなぐ」と読み替える
- v1.2（VM 側のレビュー）：ホストの規則（DOCKER-USER など）は box-manager のコンテナからは入れられない（ホストのネットワーク名前空間と `NET_ADMIN` が要る）。規則は手順書のホスト側の手順で入れ、box-manager は入っているかを確かめて、なければ VM を起こさない（D-293）。ホームの入れ替え（API-108）と控え（API-143）は裏で動かし、本体は終わりを問い合わせる。失敗はホームを `broken` にする（D-294・D-295）。つなぐボリュームはホームと控え専用の 2 つだけで、本体のデータのボリューム（SQLite の暗号化したトークン）はつながない。ホームの大きさとホストの空きを測るのは box-manager だけ（D-309）
- v1.3 の直し：Docker が別の VM にある置き先（Docker Desktop・OrbStack・Colima）ではホストの規則が効かない。box-manager は別の VM かを見分け、`isolated` モードで box ネットワークを作れたときだけ VM を起こす。作れなければ `HOST_ISOLATION_MISSING`（D-314）
- v1.4：box-manager はホストへの入りの規則の確かめ・Docker が別の VM かの見分けをしない（D-326）。ホームの測り・控え・2 コンテナを一緒に起こす役は残る
