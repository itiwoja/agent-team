# ADR-044：VM を起こせるのは box-manager だけにする
- 状態：承認（2026-10-24 にユーザーが承認：D-172） ／ 日付：2026-10-24（v0.2 で中継の役割を直した） ／ 決定者：Claude判断（提案）→ ユーザー
- 影響する ID：FR-074, API-101〜109・113, NFR-066, R-79

## 状況
VM を起こすには Docker を操作する権限が要る。Docker のソケットを持つものはホストを握れる。本体は外のページの内容と LLM を扱うので、乗っ取られる面が広い。

## 決定
Docker の権限は、別のコンテナの box-manager だけに持たせる。box-manager は「決まったイメージを決まった上限で起こす・止める・VM ごとのネットワークを作る・一覧・中継・プロフィールを消す」しか受けず、作るコンテナの中身（イメージ・マウント・権限・ネットワーク）はコードで固定する。ソケットは docker-socket-proxy を通し、使う API の種類（コンテナ・ネットワーク・ボリュームの作成と削除、イメージの読み取り）に絞る。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 本体にソケットを渡す | 部品が1つ減る | 本体が乗っ取られるとホストを握られる | 守りが薄い |
| rootless の Podman | ソケットの危うさが小さい | ラズパイ・WSL での手順が増える | 手順を1つにしたい（ADR-049） |

## 影響
- docker-socket-proxy は API の種類を絞るだけで、作成の中身までは絞れない。box-manager が乗っ取られれば、権限つきのコンテナを作られてホストを握られる（R-79 は残る）。box-manager を小さく保ち、外から届く口を ctl だけにする
- 本体と box-manager の間は共有トークンで確かめる
