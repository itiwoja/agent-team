# ADR-029：MCP の書き込みツールの引数に役割を付け、「以後も許可」のルールは宛先をすべて固定する
- 状態：承認（BR-39 を改訂） ／ 日付：2026-10-01 ／ 決定者：ユーザー（15：プロダクトオーナーが承認）
- 影響する ID：BR-39, BR-35, BR-56, BR-57, REQ-046, API-071

## 状況
BR-39 は「宛先がルールで固定された書き込みだけ `auto`」としているが、汎用の MCP ツールのどの引数が宛先かを Kernel は知らない。全引数を一致させると、毎日変わる本文のせいでルールに一致しない。

## 決定
- **引数の役割**：書き込みツールの引数ごとに `destination` / `content` / `option` を、分類と同時にユーザーが確定する。未確定の引数は `destination` として扱う。
- **ルールの一致**：ルールはツールの **すべての `destination` 引数** を完全一致で固定しなければならない。`content` はルールに書けない。`option` は書いた分だけ完全一致。
- **汚染との関係**：ルールの条件は汚染の有無にかかわらず同じ（常に宛先を固定）。BR-39 はこれに置き換える。

## 理由
宛先は定義が決め、LLM は中身だけを書く。宛先を固定すれば、本文が毎日変わっても定期実行を自動化できる。

## 代替案（これまで）
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 引数の役割なし（BR-39 が「宛先」を前提にしているだけ） | — | どれが宛先か Kernel に分からない | 上記の状況 |
| 「対象のパターン」で一致（BR-35。書き方は未定） | — | — | 完全一致に置き換え |
| 汚染時だけ引数のパターンまで一致を要求（v0.4 の BR-39） | — | — | 常に宛先を固定に置き換え |

## 影響
- 役割の確定がユーザーの手間を増やす（未決：カタログで推奨を配るか、初回の承認カードで確定するか）。
- 詳細（正規化・網羅の条件・`tool_hash`・[以後も許可] の5条件）は 04（機能仕様）。
