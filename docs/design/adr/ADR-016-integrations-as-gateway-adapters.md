# ADR-016（フェーズ2）：連携先は Gateway のアダプターとして追加し、ブラウザ操作は採用しない
- 状態：**置き換え済み**：ブラウザ操作は v0.3 で統制つきで採用（→ [ADR-019](ADR-019-browser-via-write-blocking-proxy.md)）、GitHub 以外の連携先は v0.4 で MCP に統一（→ [ADR-022](ADR-022-mcp-unified-unclassified-is-write.md)）。アダプター方式は GitHub（と将来の特別扱いが要るもの）に限って有効 ／ 日付：2026-10-01 ／ 決定者：—（元の記述なし）
- 影響する ID：REQ-030, REQ-040

## 状況
競合はブラウザ操作で API のないサービスも扱う。

## 決定（元の記述）
連携先ごとに Gateway のアダプターを作り、各作用を「内容を固定できる Intent」（プレビュー・intentHash・実行・検証）として定義する。ブラウザ操作は採用しない。

## 理由（元の記述）
ブラウザ操作は、実行する内容を事前に固定できず、承認したものと実行されたものの一致を検証できない。open-team の原則と両立しない。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| ブラウザ操作で連携する（競合の方式） | API のないサービスも扱える | 内容を事前に固定できない | 上記の理由（のち ADR-019 で統制つきで採用） |

## 影響（元の記述）
- 対応できるサービスの数では競合に劣る。よく使われる連携先から順に、深く対応する。

## 置き換えの内容
- v0.3：ブラウザは別のサンドボックスで動かし、書き込みの通信をプロキシで止める形で採用（ADR-019）。
- v0.4：サービスごとのアダプターでは対応数で dots に勝てないため、GitHub 以外は MCP コネクタに統一（ADR-022）。
- v0.3 時点のフェーズ2の連携先の設計（アダプター方式）は [07 §フェーズ2の構成](../07_architecture.md#フェーズ2の構成の概要) に残す。
