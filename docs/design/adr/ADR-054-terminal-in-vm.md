# ADR-054：ターミナルは VM の中に入れ、VM の中のコマンドは判定しない
- 状態：承認 ／ 日付：2026-10-24 ／ 決定者：ユーザー（VM にターミナルを入れる）、Claude判断（判定の線引き・通信・リポジトリの出し入れ）
- 影響する ID：REQ-094, FR-086, NFR-080, API-117, API-118, TBL-040, BR-08

## 状況
旧 Node 版には「作業場（sandbox）」があり、`run_command` などの道具を Kernel で判定し、`run_shell` は既定で拒否していた。Cloudflare 版では作業場は未定のまま（Sandbox SDK）。v0.1〜v0.3 では VM はブラウザだけで、コマンドの作業場は入れない提案だった（Q-116）。持ち主は「VM にターミナルも入れる」を選んだ。

## 決定
- VM のイメージにシェル・git・Node・Python・よく使う CLI を入れ、box-agent がコマンドを実行する（内部 API-117）。道具は旧 sandbox の 6 つ（`run_command`・`list_files`・`read_file`・`search`・`write_file`・`delete_file`）を再利用する
- VM の中のコマンドは Kernel で判定しない。VM は使い捨てで、権限なし・資源の上限つき・VM ごとのネットワークにいて、資格情報を持たない。VM の外に効くもの（push・PR・外部 API への書き込み）は VM からは直接できず、今までどおり gateway 経由の Intent と確認（FR-081）を通る
- ターミナルのプロセスは egress を「ターミナル用の資格」で通し、egress は資格ごとに許可リストを分ける。ターミナル用の既定は GitHub とパッケージのレジストリだけ（`terminal.allow_hosts`）。Chromium の通信はアドレスの判定だけで、今までどおり
- リポジトリは clone せず、gateway が GitHub から tar を取って VM に入れる（API-118。旧 sandbox の「控え」の形）。変更は tar で取り出して差分にし、PR の Intent に乗せる

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 入れない（v0.3 までのおすすめ） | 隔離の論点が増えない | コードを直す仕事を任せられない | ユーザーが入れることを選んだ |
| 許可リストのコマンドだけ（旧 sandbox の形） | 守りが明確 | 開発の仕事で止まりすぎる。許可リストの保守が要る | VM が使い捨てなので中は自由でよい |
| 全コマンドを確認に回す | 一番安全 | 開発タスクで確認が数十回になる | 使えない |
| VM に GitHub の資格情報を渡して直接 push | 流れが単純 | ページの仕掛けで資格情報が漏れる。push が確認を通らない | VM の外に効くものは確認を通す |

## 影響
- egress にプロキシ認証と資格ごとの許可リストが要る。隔離の試験に「ターミナルから許可リスト外のホスト・LAN に届かないこと」を足す
- コマンドの出力・読んだファイルは外の内容として汚染（BR-06 と同じ扱い）
- 上限は NFR-080（1 コマンド 120 秒・出力 64KB・1 タスク 200 回）。暴走は資源の上限と使い捨てで抑える（R-84）
- 人がターミナルを直接打つのは次の版。VM の画面は Chromium の全画面のまま
