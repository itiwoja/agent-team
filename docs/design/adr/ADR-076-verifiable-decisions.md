# ADR-076：判定の規則を版つきで持ち、試験・再実行・監査ログの鎖で確かめられるようにする
- 状態：承認（v1.6） ／ 日付：2026-10-26 ／ 決定者：ユーザー（差別化の軸 B）・Claude判断（形）
- 影響する ID：REQ-109, US-076, UC-065, FR-076・077・104〜106, NFR-090・091, TBL-033・035・039・057・058, `audit_logs`, API-149〜151, SCR-010・028, R-103, D-347〜350・369

## 状況
大手 3 社の承認は「どの操作で止めるか」を提供元が決めていて、外からは確かめられない。Muse には台本から外れる動きも報じられている。こちらの Kernel はもともと決定論のルールで動き、コードも読める。それでも v1.5 には、規則の版・試験・再実行・改ざんの検出がなく、「本当にこの規則で判定したのか」を後から示せなかった。

## 決定
- 判定の規則（`workspace_policies` の `browser`・`terminal`・`network` 欄と行き先の表）を正規化した JSON にする。変えるたびに `policy_versions` に版・SHA-256・変えた人・理由を残す。判定ごとに使った版のハッシュを残す。`policy.json` として書き出し・取り込みができる（D-347）
- 版の本文に入れるのは `browser`・`terminal`・`network`・`review.auto.enabled` と行き先の表。`budget`・`llm` は入れない。今の値は `workspace_policies` に置き、保存のたびに同じトランザクションで版を足す（D-369）
- 規則と一緒に試験の例（作動の入力と期待する行き先）を持つ。全部通らないと保存できない。過去 30 日の判定に新しい版を当て、行き先が変わる件数と例を見せる（D-348）
- 判定の入力（正規化した作動・確かめた中身・規則の版）を保存する。もう一度判定すれば同じ結果になる。Kernel の判定は純粋な関数にし、時刻・乱数・LLM・ネットワークを使わない（D-349）
- `audit_logs` の各行に `prev_hash`・`row_hash` を足して鎖にする。毎日の末尾のハッシュを `audit_anchors` に残して書き出せるようにし、検査で切れ目を見つける（D-350）

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 今のまま（規則は設定の JSON、監査は追記だけのトリガー） | 作りが単純 | どの規則で判定したか後から示せない。DB を直接書き換えられたら分からない | B を言い切れない |
| 汎用の規則エンジン（OPA など）を入れる | 表現が強い | ラズパイに重い。持ち主が読めない | 今の規則は表で足りる |
| 外部の透明性ログ（Sigstore など）に載せる | 第三者が確かめられる | 外に出る（ADR-074 とぶつかる） | 先頭のハッシュを自分で控える形にした |

## 影響
- 判定を残す表（`browser_actions`・`browser_checks` など）に `policy_sha256`・`verdict_input`・`decided_by` を足す
- 画面 SCR-028 を足し、SCR-010 に「誰が決めたか」・規則の版・鎖の検査の結果を出す
- ホストの root を取られた場合に守れるのは、外に控えた先頭のハッシュより前の記録だけ（R-103）。ディスクの暗号化を勧める（R-81 と同じ）
