# ADR-032：Google Cloud と Gemini は「なくては成り立たない所」にだけ使う
- 状態：承認 ／ 日付：2026-10-02 ／ 決定者：プロダクトオーナー（[D-36](../decisions.md#d-36)）
- 影響する ID：A-14, A-24, NFR-022, D-04, Q-48, [15](../15_hackathon.md)

## 状況
第5回 Agentic AI Hackathon with Google Cloud に open-team を出す（[D-35](../decisions.md#d-35)）。必須の条件は、Google Cloud の実行基盤とGoogle の AI 技術をそれぞれ1つ以上使うこと。一方で、技術を並べるだけでは評価されず、統制の中心（Kernel・gateway・汚染の追跡）を迂回する使い方は製品の価値を壊す。

## 決定
次の基準で採否を決める：**その技術がないと、製品か提出の要件が成り立たない／既存の境界をより強くする**ときだけ使う。

| 技術 | 採否 | 理由 |
|---|---|---|
| Cloud Run | 採用 | 公開 URL が必須。フェーズ1の設計（A-24）もすでに Cloud Run。境界ごとにサービスとサービスアカウントを分けられる |
| Cloud SQL | 採用 | Cloud Run の上では PostgreSQL を動かせない。状態の正本を PostgreSQL に置く設計（ADR-001・006）を変えない |
| Gemini（Gemini Enterprise Agent Platform 経由） | 採用 | エージェントの推論・設定プランナー・リハーサルの状況の生成に LLM が要る。API キーを持たずにサービスアカウントの IAM で呼べるので、「LLM を呼べるのは `sandbox-edge` だけ」（NFR-022）を鍵ではなく権限で強制できる |
| Secret Manager・Cloud Scheduler・Cloud Logging | 採用 | `.env` をイメージに入れない／最小インスタンス0のまま定期実行する／タスク ID で横断検索する。どれも Cloud Run での運用に必要な最小限 |
| Gemini を BYOK の選択肢に追加（フェーズ1） | 採用 | 開発者でない個人（v0.4 の対象）は Google アカウントを持つことが多い。Flash 系は要約などの軽いフェーズに向く。無料枠のキーは入力が学習に使われうるため、NFR-046 に照らして警告を出す |
| ADK | 不採用 | 自前の Harness・Kernel と役割が重なる。置き換えると、判定を LLM の外に置く設計（ADR-001）の検証をやり直すことになる |
| 検索によるグラウンディング | 不採用 → **[D-111](../decisions.md#d-111) で改訂：統制を通る形で採用** | 検索と取得がモデルの中で起き、GET だけの取得プロキシ（ADR-023）と汚染の追跡（ADR-024）を通らない、というのがこの時点の不採用の理由。D-111 では web_search（Gemini の Google 検索 Grounding を edge の `callGemini` 経由で呼ぶ）と web_fetch（付与されたドメインだけ）を、Kernel の判定・汚染の追跡・ドメインの付与・回数の上限・SSRF 防御をつけて入れ、この懸念は保ったまま |
| 音声・画像・Vision・翻訳 | 不採用 | 今の要件に必要な場面がない。要件ができた時点で見直す |
| Cloud Run Jobs・KMS | フェーズ1 | ハッカソン版では起動の遅さ（Q-49）と工数に見合わない。設計は残す |

## 理由
- 必須の条件を満たす最小の組み合わせが、そのまま既存の設計（07 のフェーズ1）と一致する。
- Gemini をサービスアカウントで呼ぶことで、ハッカソン版でも「鍵を持つサービスを1つに絞る」（ADR-010 の意図）を守れる。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 一覧の技術をなるべく多く使う | 「使いこなし」に見える | 必然性がなく、統制を迂回する使い方が混ざる | 分析資料の「技術スタックは無理に全部使わない」と、統制が中心という製品の筋に反する |
| AI Studio の API キーで Gemini を呼ぶ | 設定が簡単 | 鍵を Secret Manager に置き、漏えいの経路が残る | IAM で呼べる方が境界が強い |

## 影響
- **BYOK だけ（01 の制約）の例外**：ハッカソン版では、オーナーの Google Cloud プロジェクトの Gemini をゲストにも使わせる。費用は BR-62 の上限で抑え、フェーズ1では BYOK に戻す。
- **フェーズ0-H のサービスの数**：ハッカソン版では runner・sandbox-edge を `app` の中のパッケージにする（[D-52](../decisions.md#d-52)）。上の「LLM を呼べるのは `sandbox-edge` だけ」は、フェーズ0-H では「`sa-app` だけ（呼ぶコードは edge のパッケージだけ。runner のパッケージは Vertex AI のクライアントを import しない）」と読み替える。フェーズ1では元に戻す。
- A-14 に `google` を加える（provider の列挙：04 policy-and-schema、08 TBL の `provider`、09 auth-workspace）。
