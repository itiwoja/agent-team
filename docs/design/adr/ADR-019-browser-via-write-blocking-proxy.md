# ADR-019（フェーズ2）：ブラウザ操作は、書き込みの通信をプロキシで止める形で採用する（v0.3）
- 状態：承認（[ADR-016](ADR-016-integrations-as-gateway-adapters.md) のブラウザ操作の部分を置き換え） ／ 日付：2026-10-01 ／ 決定者：—（v0.3 の方針「統制つきで同等に」はユーザー決定）
- 影響する ID：REQ-040, REQ-041, BR-37

## 状況
ADR-016 では、内容を事前に固定できないためブラウザ操作を採用しなかった。競合と同等にするには必要。

## 決定
- ブラウザは別のサンドボックスで動かし、通信をプロキシで制御する。
- GET / HEAD は許可したドメインだけ。それ以外は、承認済みの Intent（送信先・入力値・送信直前の画面のハッシュ）に一致する場合だけ通す（BR-37）。
- ログイン情報は保管庫に置き、ブラウザの実行環境だけが入力に使う（モデルには見せない）。

## 理由
画面の操作そのものではなく「外に出ていく書き込み」を決定論的に止めるので、承認した内容と実行された内容の一致を、通信の単位で検証できる。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| ブラウザ操作を採用しない（ADR-016） | 原則と両立 | 競合と同等にならない | v0.3 の方針 |

## 影響
- GET で状態が変わるサイト（行儀の悪いサイト）は防げない。許可するドメインを絞って運用で補う。
- プロキシで扱えない通信（WebSocket など）は、既定で遮断する。
- ブラウザのサンドボックスの基盤は未決（[07 Q-49](../07_architecture.md#-判断してほしいこと)）。
