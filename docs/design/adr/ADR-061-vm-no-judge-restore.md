# ADR-061：VM の中のコマンドは判定せず、資格情報を置かず、毎日の控えから戻せるようにして守る
- 状態：承認 ／ 日付：2026-10-24 ／ 決定者：ユーザー（判定せず戻せるように）、Claude判断（利用者の分け方・控えの数）
- 影響する ID：REQ-094, REQ-104, FR-086, FR-100, NFR-066, NFR-080, BR-08, TBL-052
- 置き換えるもの：[ADR-054](ADR-054-terminal-in-vm.md)（「VM は使い捨てだから判定しない」の理由の部分。ターミナルの道具・egress の資格・tar の出し入れはそのまま引き継ぐ）

## 状況
ADR-054 は「VM はタスクごとに使い捨て」を理由に、VM の中のコマンドを判定しなかった。ADR-060 で VM は残り続け、ログインも共有になるので、この理由が成り立たない。

## 決定
- VM の中のコマンドは、今までどおり Kernel で判定しない
- 資格情報（GitHub・カレンダーのトークン・API キー）は VM に置かない。VM の外に効くもの（push・PR・外部 API への書き込み）は gateway の Intent と確認を通る（今のまま）
- 外への通信は egress の許可リストだけ（ターミナル用の資格・`terminal.allow_hosts`。今のまま）
- Chrome は利用者 `browser`、コマンドは利用者 `agent` で動かす。Chrome のプロフィールのフォルダは `browser` だけが読める（700）。コマンドから Cookie を読めない
- ホームのボリュームを毎日 1 回、控え（tar）に取る。3 世代。持ち主は画面から控えに戻す・空から作り直すことができる（FR-100）

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 危ないコマンドを合図に入れる | 守りが厚い | 形を変えればすり抜ける。開発の仕事で止まる | ユーザーが選ばなかった |
| 仕事ごとに使い捨ての作業用のコンテナを別に立てる | 汚れが残らない | VM 1 台の前提が崩れる | ADR-060 と合わない |

## 影響
- 隔離の試験に「コマンドの利用者から Chrome のプロフィールを読めないこと」を足す
- 控えは控え専用のボリューム（`makase-vm-snapshots`）を使い、box-manager は本体のデータのボリュームをつながない（v1.2・D-309）。ホームの上限 4GB・3 世代で、書きかけを入れて最大 16GB（圧縮が効かないとき）。NFR-062 の空きディスクを 32GB にする（v1.2・D-300。v1.0 は 20GB）
- v1.2（VM 側のレビュー）：利用者を分ける（`browser`・`agent`）には、起こすときの「capability をすべて外す」と両立させる必要がある。VM の起動役だけが `CAP_SETUID`・`CAP_SETGID` を持ち、子を起こしたら手放す。`hidepid` は使えないので頼らず、トークン・X の鍵は fd で渡す（D-290・D-291）
- v1.2：戻し・作り直しに失敗したら、ホームを `broken` にして戻す・作り直すだけを受ける（D-294）
- v1.3 の直し：控えに入るのはホームだけ。Chromium の HTTP キャッシュは `/tmp/chromium-cache` にあり、控えにも戻しにも関わらない（D-313）
