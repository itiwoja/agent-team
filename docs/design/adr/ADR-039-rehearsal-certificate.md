# ADR-039：リハーサルの合格証がないとルールの自動を使わず、本番で止まったことは次の試験になる
- 状態：承認 ／ 日付：2026-10-02 ／ 決定者：プロダクトオーナー（[D-77](../decisions.md#d-77)・[D-78](../decisions.md#d-78)）
- 影響する ID：REQ-070・071（新規）, FR-066・067（新規）, FR-042〜045, BR-80・81（新規）, BR-39, O-08（新規）, ADR-022, ADR-033, ADR-035, D-19, D-57

## 状況
ADR-033 のリハーサルは「仕事を有効にする前に1回試す」もので、試した後に条件が変わっても結果は古いまま残る。ポリシーを広げたとき・MCP ツールの説明（`tool_hash`）が変わったとき・モデルを替えたときに、ユーザーは「前に合格したから大丈夫」と思い込みやすい。また、本番で Kernel が止めたことやユーザーが却下したことは監査ログに残るだけで、次の試験には生かされない。プロダクトオーナーは「量は減らさず、プロダクトとして強くする改善」を求め、リハーサルを任せたあとも効く仕組みにすることにした。

## 決定
- 仕事ごとに **試験の集合**（`rehearsal_cases`。`generated` / `user` / `incident`）を持つ。
- 本番で Kernel の `approve` / `deny`・送る前の確認の却下・実行中の Kill Switch が起きたら、そのタスクの開始時の `sim` の状態・シード・`reason_code` から決まる障害 ID を `incident` の試験として自動で加える（BR-80）。合否には O-08「同じ書き込みが確認なしで実行されていない」を加える。
- 試験がすべて合格したら **合格証** を出す。中身は `policyHash`・`tool_hash` の集合・モデル ID・試験の集合のハッシュ・結果で、ハッシュを監査ログのハッシュチェーンに入れる。
- 広げる変更の適用・`tool_hash` の変化・モデルの変更・試験の追加で合格証は切れ、今の試験で自動で再リハーサルする。
- **合格証がない・切れている仕事では、`decide()` の手順11でルールによる `auto` を使わず `approve`（`certificate_missing`）にする**。手順9（`unknown_outcome`）・手順10（ガード）・汚染・宛先の固定は変えない。

## 理由
- ルールは「確認を省いてよい」という許可で、その許可の裏付けがリハーサルの合格になる。裏付けが切れたら許可も止まる、と結びつけると、「試していない条件で確認なしに書き込む」状態がそもそも作れない。
- 条件の追加は `approve` を増やす方向だけ（締める方向）なので、Kernel の不変条件（LLM は締める方向にしか判定を動かせない・BR-39 の「汚染の有無で判定を変えない」）を壊さない。
- 本番の停止を試験にすると、「使うほど試験が増え、同じ事故の型が二度と確認なしで通らない」ことを決定論で保証できる。LLM に覚えさせる（記憶・プロンプトの追記）と違い、揺らがず、監査できる。
- 合格証のハッシュを監査ログに入れると、「いつ・どのポリシー・どのツール・どのモデルで合格していたか」を後から検証できる。審査基準の「管理・可観測性」に直接答えられる。

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| 合格証は表示だけにし、判定には使わない | 確認が増えない | 切れていても確認なしで書き込める。表示を見落とせば意味がない | 裏付けと許可を結びつけるのがこの決定の核 |
| 合格証が切れたら仕事そのものを止める | いちばん安全 | 読み取りや確認つきの書き込みまで止まり、毎日の仕事が途切れる | ルールの `auto` を止めるだけで、確認なしの書き込みは防げる |
| 本番の停止を LLM が要約して次の状況の生成に渡す | 実装が軽い | 同じ事故の型が試験に入る保証がない。揺らぐ | スナップショットとシードで決定論の試験にする |
| 締める変更でも合格証を切る | 一貫している | 締めるたびに再リハーサルが走り、費用と待ちが増える | 締める変更は FR-045 の再試験で足り、許可は増えない |

## 影響
- 04 の `decide()` の手順11に合格証の確認を足す（`reason_code = certificate_missing`）。ハッカソン版は 15 を正とし、04 への反映は提出後。
- 用意した依頼（D-70）は「合格証なし」で始まり、審査員が [適用] → 再試験で合格証が出るのを見る。用意した送る前の確認（豆 20kg）はもともとルールのない承認なので変わらない。
- 新しいテーブル `rehearsal_cases`・`rehearsal_certificates`（08 への反映は提出後）。
- フェーズ0（実のコネクタ）で本番の読み取り結果を試験に保存するかは Q-113 で決める。
