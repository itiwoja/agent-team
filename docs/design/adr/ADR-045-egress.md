# ADR-045：VM は1つずつ別のネットワークに置き、外への通信は egress だけを通す
- 状態：承認（2026-10-24 にユーザーが承認：D-172） ／ 日付：2026-10-24（v0.2 で VM ごとのネットワークにした） ／ 決定者：Claude判断（提案）→ ユーザー
- 影響する ID：NFR-066, R-76

## 状況
VM は信用しないページを開く。ページの中の仕掛けで、家の LAN の機械・ルーター・tailnet の端末・本体・ほかの VM に届かれては困る。Docker の `internal: true` は外への道をなくすだけで、同じネットワークの中どうしは届く。

## 決定
- VM ごとに `internal: true` のネットワークを作り、VM・box-manager・egress の3つだけを入れる。VM には DNS を持たせない
- egress は HTTP(S) のプロキシ。名前を引いて返ったアドレスを全部確かめ、1つでもグローバルでない（IANA の特別用途の範囲：0/8・10/8・100.64/10・127/8・169.254/16・172.16/12・192.0.0/24・192.168/16・198.18/15・224/4 以上・`::`・`::1`・`::ffff:0:0/96` を IPv4 に直したもの・`64:ff9b::/96`・fc00::/7・fe80::/10・ff00::/8 など）なら断る。つなぐ先は確かめたアドレスに固定する（名前を引き直さない）
- egress の外への道（egress-out）は、本体の外への道（core-out）と別のネットワークにする

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| VM を1つのネットワークにまとめる | 簡単 | VM どうしが届く | 隔離できない |
| ホストの iptables の規則 | 部品が要らない | WSL2・Mac の VM・ラズパイで書き方と効き方が違う | 置き先を選ぶ |

## 影響
- WebRTC や QUIC のような HTTP 以外の通信は通らない。断った通信は egress のログに残す
- 隔離の試験に、VM どうし・ホストのブリッジのアドレス・管理の口・IPv6・名前の引き直しを入れる
- `web_fetch` にも同じアドレスの判定を適用する（D-164）。リダイレクト先も確かめ直す
