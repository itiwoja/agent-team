# ADR-081：家電・IoT は Home Assistant 経由にし、こわい機器は規則で必ず人に聞く
- 状態：承認（v1.7） ／ 日付：2026-10-26 ／ 決定者：ユーザー（Home Assistant 経由）・Claude判断（機器の区分）
- 影響する ID：REQ-115, US-081, UC-070, FR-113, TBL-062, API-155, SCR-032, BR-15, R-107, D-377・378

## 状況
非エンジニアが「玄関が開いたら知らせて」のような IoT を頼めることが、家に置く利点になる。マイコンのプログラムまで書かせると配線が要り、非エンジニアには難しい。家電は画面の中の操作と違い、鍵・暖房・ガスのように物理的な害が出る。

## 決定
- 同じラズパイに Home Assistant のコンテナを入れる（キットでは入れておく）。本体のコネクタが HA の API を長期トークンで呼ぶ。トークンは本体に暗号化して置き、VM には置かない。HA は内部ホストとして自動で登録する（D-377）
- できること：機器の状態を読む・動かす、自動化を作る・直す・消す。機器の写しを `home_devices` に持つ
- 機器の区分（D-378・BR-15）：鍵・空調と暖房・ガスと水のバルブ・警報・シャッターやガレージと、持ち主が「こわい」に印を付けた機器を動かす、またはそれらに触る自動化を作る・変えるのは、必ず人の確認。ほかの機器を動かすのは通す。自動化を作る・変える・消すのは、既定で人の確認
- 区分は Kernel の規則で決め、規則の版に入る（ADR-076）。判断モデルや LLM では決めない（BR-16）

## 代替案
| 案 | 良い点 | 悪い点 | 不採用の理由 |
|---|---|---|---|
| マイコン（ESP32 など）まで作る | 自由 | 配線が要り、非エンジニアに難しい。書き込みの失敗で壊れる | Home Assistant を選んだ（ユーザー） |
| 機器はどれも通す | 速い | 鍵を開ける・暖房を付けっぱなしにする | 物理的な害は取り返しがつかない |
| 機器はどれも人に聞く | 安全 | 「電気消して」でも止まる | 便利さが消える |

## 影響
- 画面に家電（SCR-032）を足し、こわいの印を持ち主が付けられる
- 試験に「鍵を動かす・鍵に触る自動化は必ず人」を足す（11）
