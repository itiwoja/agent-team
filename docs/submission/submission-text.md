## 1. 短い版（約225字）

頼むだけで、あなたの担当が生まれる。Makase に「仕入れ先のメールを読んで、在庫を見て、必要なら発注して」と一言頼めば、Gemini が担当を作って手分けします。似た依頼にはふつう同じ担当が動き、引き継がれたルールや権限を絞った設定は、その依頼で安全チェックを通すと効いて確認が減ります（安全チェックの中の実測：32回→17回、損害 ¥0。使い回しの効果は未測定）。任せても大丈夫な理由は、書く前に必ず止める統制と、悪い日を試す安全チェックです。

字数：225字（改行・記号を含めた数え方。Python の `len` で数えた）。位置づけの変更（エージェントは、エンジニアなら自分で作れるが一般の人は作れない。Makase は依頼から担当を作り、似た依頼にはふつう同じ担当が動く）を1〜2文目に置き、安全チェックと統制は「任せても大丈夫な理由」として最後に残した。使い回しで確認が減るのは、引き継がれたルールや権限を絞った設定を、その依頼で安全チェックに通したあと（承認した宛先や安全チェックの記録は仕事ごとで、引き継がれない）。「32回→17回」は、安全チェックの中で、ルールを足し権限を絞った場合に同じ仕事について35走行で測った値（確認の回数）で、使い回しの効果そのものは測っていない。利用者が何日も使った推移でもない。字数のために、旧版の「統制なしの損害 ¥234,000 が ¥0」は短い版から外した（長い版・動画に残している）。

## 2. 長い版（800字程度）

> 目安：約800字

**課題**　エンジニアなら、エージェントを自分で組めます。でも、小さな店の店主のようなふつうの人は、担当の分け方・権限・指示文を書けず、「AI に任せる」が始まりません。書けたとしても、「変なメールが来た日」「API が落ちた日」に何をするかは、本番で事故が起きるまで分かりません。だから Makase は、エージェントを作る作業を引き受け、任せる前に、その仕事の悪い日を作って試します。

**なぜエージェントか**　ルールに書けない判断（メールの中身を読んで、いまの在庫と照らして発注量を決める）はエージェントにしかできません。だからエージェントに任せ、悪い日だけを統制で止めます。

**解決**　Makase は、エージェントを作れない人のための製品です。「仕入れ先のメールを読んで、在庫を見て、必要なら発注して」と一言頼むと、Gemini が担当（受信箱係 → 仕入れ係）と設定を作り、手分けして片付けます。読む担当は書けず、発注する担当はメールを直接読みません。似た依頼が来たら、新しく作らず、ふつうは同じ担当（画面では「いつもの担当」。選ぶのは Gemini で、必ずではありません）が引き受けます。担当に引き継がれた「以後も許可」のルールや権限を絞った設定は、その依頼で安全チェックを通すと効き、確認が減ります。あなたに届くのは送る前の確認のような「見てほしいもの」だけで、○ を押せば本物になります。

**任せても大丈夫な理由**　任せる前に、Gemini がその仕事の悪い日を作り、模擬の世界で本番と同じ統制（Kernel）のもとで試します（安全チェック）。止めたもの・すり抜けたものを、防いだ損害の金額（円）つきで見せ、穴は権限を絞る変更だけで塞いで試し直します。全部止まるまでは、ルールがあっても確認に回します。安全チェック済みの仕事で、本番で [送らない] にした発注は、次の安全チェックに足され、自動で試し直します。審査員は、自分の言葉で書いた悪い日もその場で試せます。

**実測**　統制なしの Gemini（`gemini-3.8-flash`）を同じ悪い日に状況ごと5回ずつ走らせると、二重発注と割高な仕入れは5回中5回起きました（仕込まれた指示と宛先のすり替えは5回とも防ぎました）。翌日、本番と同じ経路で測り直すと、統制なしの損害 ¥234,000 が統制ありでは ¥0（統制なしの失敗は日によって揺れます）。「以後も許可」のルールで確認を減らすと割高な仕入れがすり抜けましたが、安全チェックが出す単価の上限を当てると、確認を32回から17回に減らしても損害は ¥0 に戻りました（安全チェックの中で、ルールを足し権限を絞った場合に同じ仕事について測った数字です。使い回しの効果そのものは測っていません。条件・全文は `docs/submission/measurements/`）。

**設計の核**　Gemini が担うのは、エージェントの推論・編成の生成、安全チェックの悪い日を考える・自分の言葉の悪い日を状況に当てはめる、調べものの要約と出典（Web 検索）です（権限を絞る提案は決定論のコードが作ります）。合否はオラクル（決定論の不変条件）、実行を許すのは Kernel、損害額は世界ごとに固定した式、安全チェック済みの印（設計上の名前は合格証）はハッシュで決まり、監査ログのハッシュチェーンに残ります。書き込みは別サービス gateway だけが出口で、実の外部サービスへの書き込みはありません（調べものの読み取りは `web_search`・`web_fetch` で、取得本文は untrusted として汚染扱い・付与されたドメインだけ・回数上限・SSRF 防御つき。[D-111](../design/decisions.md#d-111)）。

**使う Google Cloud**　Cloud Run（app・gateway・sim-world の3サービス）、Gemini（Vertex AI 経由、API キーなし・IAM で呼ぶ）、Cloud SQL、Secret Manager、Cloud Scheduler。

> 注記（正直に書く）：ゲストが最初に開く「用意した依頼」の結果と、その再試験は、エージェントの振る舞いを台本にして再現したもので、毎回同じ結果になる（Kernel・ガード・模擬の世界・オラクルは本物。Gemini は呼ばない）。自分で頼んだ依頼のリハーサルと、自分の言葉で書いた悪い日は本物の Gemini で走る。提出文・動画で「Gemini が走らせた」と言い切らない。

- 「試験の合否を決まったコードで出す」の列は、事前の試験の合否のこと。本番で止めるかどうかの判定が決定論かは別の話で、固定ルール・SDK の承認の条件・AgentCore の Cedar はそちらに当たる（本番の判定は Makase では Kernel の `decide()`）。

既存の道具は、それぞれ得意な場所が違います。本番で止める道具（承認・ガードレール・ポリシー）と、開発者が品質を測る道具（レッドチーミング・シミュレーション試験・評価）はすでにあります。Makase が足したのは、その間をつなぐ一周です：**自分の業務の悪い日を、本番と同じ統制で試し、損害を円で見て、締める変更で塞ぎ、試験に通るまでは自動にしない**。Makase はこれらと競うより、組み合わせて使えます（たとえば入力の検査に Model Armor を足す）。

公平のための注記：「本番の事故を次の試験に」は、LangWatch Scenario も掲げています [13]。Gemini Enterprise Agent Platform も、本番の通信を採点する online monitor と、session traces から評価のデータセットを作る機能を持ちます [11][12]。Langfuse も、本番の trace を「+ Add to dataset」で試験のデータセットに入れられます [20]。「事前に試す」「道具の失敗・遅延を模擬する」は Gemini Enterprise Agent Platform の評価にもあります [11][12]。Amazon Bedrock AgentCore の Policy は、決定論の規則（Cedar）、本番の通信を止めずに確かめるモード（LOG_ONLY）、自然文からの規則づくり、広すぎる規則の静的な検出を持ちます [7][8]。Makase の違いは個々の機能ではなく、これらを店主が画面で回せる一周にまとめ、損害を円で出し、締める方向の変更だけを提案し、合格証がないと自動にしないところです。なお、ゲストが最初に開く用意した依頼の結果と再試験は台本の再現で、本物の Gemini で走るのは自分で頼んだ依頼のほうです（§2 の注記）。

### 3-3. 一言の違い（短くしたいとき）

| 既存の選択肢（代表例） | 得意なこと | Makase が足すこと |
|---|---|---|
| 人が毎回確認する | 確実。ただし毎回、人の手間がかかる | 確認が要るものだけに絞り、その根拠を再試験で示す |
| 固定ルールの自動発注 | 決まった条件で確実に動く | メールの中身のような、ルールに書けない判断はエージェントに任せ、悪い日だけを統制で止める |
| エージェント製品・SDK の承認、ガードレール、ポリシー（Grok Bot、Zapier、OpenAI Agents SDK、Model Armor、Amazon Bedrock AgentCore の Policy など） | 本番で、危ない操作を止める・人に聞く | その止め方で足りるかを**任せる前に**悪い日で試し、足りない所は権限を絞る |
| レッドチーミング・シミュレーション試験（promptfoo、Gemini Enterprise Agent Platform の Agent Simulation、LangWatch Scenario など） | 開発者が、本番の前に品質と弱点を測る | 店主が画面で、自分の業務の悪い日を試せる（いまの版は仕入れの業務）。結果を**損害の円**で見せ、塞ぐ変更は**権限を絞る方向だけ**、全部止まるまで自動にしない |
| 観測・評価（Langfuse など） | 本番で何が起きたかを記録して追う。trace を試験のデータセットに入れ、回帰を CI で測る | 本番で止まった発注を、状態のある模擬の世界の悪い日として次の安全チェックに足し、自動で試し直す |
